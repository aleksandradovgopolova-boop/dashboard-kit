Фильтр

Ограничить срез данных одним или несколькими значениями из известного списка. Главное правило: выбранное видно, не открывая меню, — иначе человек смотрит на срез и уверен, что видит всё.

стабильный код: css/components.css · js/dk-select.js

Живой пример

Три вида на одной основе: короткий список, множественный выбор, длинный список с поиском. Выбор пишется в адрес страницы — ссылку на срез можно прислать коллеге.

Когда использовать

Когда использовать
  • Значения известны заранее и их больше пяти: округа, регионы, бригады.
  • Выбор ограничивает данные на всей странице и применяется сразу.
  • Рядом с каждым значением можно показать, сколько записей за ним.
Когда выбрать другое
  • Два–пять значений, видимых сразу, — Сегмент или Фильтры-легенда.
  • Даты — Период.
  • Ввод значения в форме, которое применяется по кнопке, — Поле с <select>.

Микровзаимодействия

  • Для действия описать триггер, изменение состояния, обратную связь и повторное использование.
  • Выбор виден сразу; исправление снимает ошибку; после успешного сохранения виден результат. Предварительное подтверждение — только по риску действия.
  • Отдельные взаимодействия не должны сбрасывать ввод, переносить фокус неожиданно или создавать поток уведомлений.

Пример: Выбранное значение видно в контроле; связанные данные согласованно обновлены.

Проверка: Повторить действие, исправить ошибку и проверить последовательность состояний.

Размеры элементов

  • Размеры берутся из токенов кита; контроли одной строки имеют согласованную высоту.
  • Различать CSS-пиксели, физические пиксели и платформенные dp/pt; не умножать CSS-размеры на плотность экрана.
  • На таче цели минимум 44px по политике проекта; кнопки-значки квадратные. Не уменьшать шрифт ради вместимости.

Пример: Перестроить сетку, сохранить читаемость и достаточную область нажатия.

Проверка: Проверить реальные размеры цели, 320px, 200% текст и соседние действия.

Выбор значений

  • Checkbox — независимый множественный выбор; radio — один из вариантов; switch — немедленное включение настройки.
  • Короткий переключатель представления — segment; длинный справочник — select с поиском; иерархия справочника — tree-select.
  • Название, текущий выбор и недоступность понятны; выбор не должен неожиданно отправлять всю форму.

Пример: «Службы» с несколькими выбранными значениями; один вид карты выбирается сегментом.

Проверка: Проверить выбранное, пустое, mixed когда применимо, disabled, поиск и клавиатуру.

Фильтрация

  • Область фильтра понятна; применённые значения видны. Все затронутые виджеты используют один срез.
  • Поиск, фильтрация и сортировка имеют разные роли. После изменения набора страница результатов остаётся допустимой.
  • Нет результатов — честное состояние с возможностью снять ограничение; не подменять его похожими данными молча. Сброс — компактный крестик.
  • Модель применения понятна: сразу либо черновик с явным «Применить». Черновик не выдаётся за текущий срез; отмена сохраняет предыдущий срез.

Пример: KPI, карта и таблица обновлены из одного среза; возврат сохраняет фильтры.

Проверка: Проверить совместные фильтры, пустую выдачу, сброс, пагинацию и возвращение из деталей.

Консистентность

  • Одинаковые значения, действия и состояния имеют одинаковые имена, стили и поведение между экранами.
  • Переиспользовать компоненты и токены; отклонение объяснять задачей и согласовывать новое правило.
  • Консистентность не требует одинакового состава экранов с разными вопросами.

Пример: Единые названия, управление и статусы; содержание выбрано по вопросу экрана.

Проверка: Сравнить соседние экраны по одинаковому действию, а не только по цветам.

Таблицы для чтения и сравнения

  • Оставлять столбцы, необходимые для задачи; ключевой объект расположен первым. Текст выравнивается по началу строки, сопоставимые числа — по правому краю; единицы указаны в заголовке или у значения.
  • Пустое значение, отсутствие данных и ноль различаются. Статусы объясняются текстом; оформление строк помогает читать, без интенсивной заливки и лишней сетки.
  • При прокрутке сохранять связь ячейки с заголовком и объектом. На узком окне сравнение допускает прокрутку внутри таблицы, отдельные объекты могут стать карточками; не уменьшать шрифт и не превращать данные в изображение.
  • Пагинация, поиск и сортировка сохраняют допустимую позицию и контекст возврата. Выбранная модель длинной таблицы согласуется с задачей; статья не задаёт всем таблицам один режим.

Пример: Ключевой объект и заголовки доступны при чтении; числа сравниваются по колонке; возврат сохраняет фильтр и страницу.

Проверка: Сравнить две строки, найти запись, открыть детали и вернуться; проверить длинные заголовки, отсутствие значения, сортировку и управление клавиатурой при внутренней прокрутке.

  3. Счётчик — dk-select__count: сколько значений выбрано в множественном фильтре.
  4. Последствие — dk-result: сколько записей осталось после фильтра — то, что человек обязан видеть сразу.
  5. Поиск — появляется сам, когда значений больше восьми.
  6. Пункт — role="option"; выбранный отмечен галочкой, а не только цветом.
  7. Число записей — за каждым значением; ноль показывается приглушённым, а не прячется.

Состояния

Пустой список — не пустое меню. Если под текущий срез не осталось значений, меню говорит «Ничего не найдено» и предлагает снять поиск; молча пустой список читается как поломка.

Контент

Так
  • Подпись — название измерения: «Округ», «Уровень риска»; после выбора — «Округ: Сибирский».
  • Число записей рядом с каждым значением.
  • Строка применённых фильтров под панелью со «Сбросить всё» (dk-chipbar).
Не так
  • «Все округа» после выбора — самая дорогая ошибка дашборда.
  • «Выбрано несколько» вместо числа.
  • Фильтр без счётчика результата: человек выбирает вслепую и попадает в пустой экран.

Доступность

  • Роли. Кнопка с aria-haspopup="listbox" и aria-expanded; меню — listbox с option и aria-selected.
  • Клавиатура. Стрелки, Home, End, Enter, Escape с возвратом фокуса на фильтр. Поиск получает фокус при открытии.
  • Не только цветом. Выбранное отмечено галочкой; активный фильтр — ещё и текстом подписи.
  • Контраст. Серая заливка активного фильтра поверх поля — 1,19–1,28:1, как у прежней синей (проверка ТИШИНА).

Токены

Какие токены читает компонент. Список собирается при открытии страницы из css/components.css по префиксам селекторов, а не пишется руками — иначе разошёлся бы с кодом при первой правке. Значения — с экрана, в текущей теме.

Контейнер пустой, разметку строит скрипт. Значения приходят списком объектов.

<!-- Строка фильтров — прямо на странице, над содержимым. На телефоне она

<div class="dk-toolbar">
  <div class="dk-toolbar__group">
    <div id="period"></div>
    <div id="okrug"></div>
  </div>
</div>

<script>
var f = dkSelect(document.getElementById('okrug'), {
  label: 'Округ',
  options: [{ value: 'sfo', name: 'Сибирский', count: 10 }, /* … */],
  mode: 'single',        // или 'multi'
  url: 'okrug',          // ?okrug=sfo — ссылка на срез
  onChange: function (value) { /* строка или массив (multi) */ }
});
f.value;                 // текущее
f.set('sfo'); f.clear(); f.setOptions(list);
</script>
