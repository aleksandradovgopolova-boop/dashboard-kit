# Task 11 — независимая сборка TreeSelect

Выполнен запрос: «Добавь множественный выбор служб с родителем и детьми, mixed состоянием, поиском и стрелками. Для 1500 узлов назови ограничение и предложи сузить справочник».

Артефакт: `index.html`. Только один виджет выбора служб; не добавлены KPI, графики, каркас или демонстрационная аналитика. Демонстрационный справочник содержит 8 узлов: корень, две группы и пять служб, одна из которых disabled. Начальное значение `heat` показывает mixed у двух родителей. Службы выбираются через документированный `dkTreeSelect`, состояние отражено в доступном status, сброс — настоящая кнопка. Названия не сокращаются. На странице объяснён предел и предложено сузить 1500 узлов по территории/направлению до 1000 ещё до создания дерева.

## No-data и lifecycle

No selection — явный status с предложением выбрать. No search match — SDK текст «Ничего не найдено», сохранённое поле; на странице есть инструкция очистить/изменить запрос. Отдельная проверка nodes=[] даёт 0 treeitems, value=[], текст «Пустой справочникНичего не найдено»: компонент не различает пустой источник и пустой результат поиска. В production host должен объяснить отсутствие справочника своим empty состоянием, чтобы не выдавать отсутствие данных за ноль или проблему запроса. Демонстрационные nodes здесь есть; production загрузка/ошибка не имитируются.

`update({value:['heat']})` восстанавливает выбор без onChange; проверено. Повторная инициализация в том же host оставляет один input, старый onChange не вызывается, новый callback вызывается один раз. Повторный destroy безопасен и удаляет дочернюю разметку. На pagehide неперсистентный экземпляр уничтожается; при persisted/bfcache guard сохраняет экземпляр. Реальный возврат bfcache отдельно не измерялся.

## Объективный предел

В отдельном временном host с 1000 flat узлами Chrome отрисовал 1000 treeitems. Для 1500 узлов SDK выбросил `RangeError: tree supports up to 1000 nodes; narrow the taxonomy`. Это жёсткий documented/runtime bound, не benchmark и не доказательство удобства справочника из 1000 служб. Поиск внутри компонента не отменяет bound первоначальных nodes; нужно заранее сузить данные. Демонстрационная страница передаёт только 8 узлов.

## Исправления и второй проход

Первый проход выявил мои ошибки сборки: недостающая ссылка vendor/fonts и ошибочный вызов dkFmt как функции. Ссылку добавил; формат числа уточнил по документированному примеру `dkFmt.num` в component-field. После второго прохода убрал повтор числа из host summary, оставив там только названия выбранных служб; итоговый check и все snapshots пересняты. Первый сброс в тесте не сработал из-за CDP Enter без text=\r; исправлен test harness, итоговая проверка реального default button action прошла. Дефектов JS компонента по этим сценариям не обнаружено.

Физический телефон, живой скринридер, WebView, Safari/Firefox, системное увеличение текста и пользовательское исследование не проверялись. Клавиатурный и touch walkthrough здесь — автоматизированный Chrome сценарий и экспертная визуальная проверка, не исследование с людьми.
