## Бриф и последовательный смысловой проход

Владелец программы выбирает регион для разбора отклонения от дневного плана. Нужны общий факт, процент исполнения, ставка с весом объёма, ежедневное сопоставление факта и плана, сравнение регионов и реальные региональные детали. Целевые viewport: 390×844 и 1280×900 в Dark/Light.

Рецепт plan-fact подходит: факт и план имеют одну единицу (кредитов), один период и одну популяцию. Три равноправных KPI отвечают на заявленные вопросы; четвёртый KPI плана не дублируется, план доступен на сравнительном графике и в региональной таблице/деталях. Две серии столбцов сравнивают дни; таблица сравнивает два региона по факту, плану, выполнению и ставке. Карта не нужна: источник использует две условные группы без геокодов, географического вопроса нет. Причины отклонений не выдуманы.

Выполнены последовательно аналитический и редакторский проходы одним исполнителем; независимым ревью это не называется. Новых агентов не создавал.

## UX · контракт и редакционный аудит

По исходному renderer проверены привязки: одна query для KPI/chart/table; детали рассчитывают выбранную группу с сохранённым каналом и днями; закрытие через настоящий `dkModal`; сброс hidden при отсутствии активных фильтров. Обзор и детали имеют data-dk-screen scope. Это проверка кода, не наблюдение в браузере.

Постоянный текст обычного состояния: название экрана; краткое «Учебные данные»; период и реальное время обновления; названия/единицы KPI; фильтры; названия виджетов/легенда/заголовки таблицы; действия. Определения и формулы открываются одним входом «Данные и методика». Пустое пересечение показывает краткое «Нет результатов» с доступным сбросом. Partial/null сохраняют краткий статус, объяснение по запросу. Постоянных объясняющих абзацев в обычном состоянии не добавлял (assembly-rules §7).

Применимые UI/UX сценарии: UI-002 (feedback после фильтра), UI-003 (единицы и предметные названия), UI-006/UI-010/UI-039 (открытие/закрытие деталей и фокус), UI-005/UI-026/UI-030 (пояснения по запросу). Структурное соответствие коду не доказывает визуальное и клавиатурное соответствие; всё это ожидает браузерной приёмки родителем.

## Реальные selectors / API для независимой browser-приёмки

```js
const root=document.querySelector('[data-dk-screen-config]');
const api=root.dashboardScreen;
api.getSnapshot(); // status, query, values, rowCount
api.setFilters({region:['Север']});
api.setFilters({channel:['Онлайн']});
api.setFilters({region:['Юг'],channel:['Отделение']}); // empty
api.reset();
```

- KPI: `[data-screen-kpis] [data-metric="issued"]`, `[data-metric="execution"]`, `[data-metric="weighted-rate"]`; значение `.dk-metric-lg`.
- Фильтры: `[data-screen-filters] .dk-select` в порядке Регион, Канал; триггеры/варианты с accessible label из `dkSelect`.
- Сброс: `[data-dk-reset]` (hidden без фильтра).
- График: `[data-screen-widget="daily-chart"] .dk-chart`.
- Таблица: `[data-screen-table="region-table"]`; строки `tr[data-group="Север"]`, `tr[data-group="Юг"]`.
- Открытие деталей: `[data-open-details="Север"]` или `[data-open-details="Юг"]`.
- Диалог: `dialog[data-dk-screen="detail"]`; дни `dialog .dk-table tbody tr`; закрытие `dialog form[method="dialog"] button`, Escape штатного modal.
- Empty: `[data-screen-empty]`; content `[data-screen-content]`; статус `[data-screen-status]`; root `data-status`.
- Методика: `[data-screen-info]`.
- Темы: `[data-theme-set="dark"]`, `[data-theme-set="light"]`.
- Нормализованный config: `JSON.parse(document.getElementById(root.dataset.dkScreenConfig).textContent)`; для изолированной проверки partial/null можно клонировать config и переинициализировать `dkScreen(root, clonedConfig)`, затем восстановить исходный config. Сетевого loader/API изменения данных у screen-spec/1 нет.
