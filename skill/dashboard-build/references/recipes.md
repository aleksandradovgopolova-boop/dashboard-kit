# Сценарные рецепты

Выбирай после брифа из SKILL.md. Рецепт — способ ответить на вопрос,
а не обязательная сетка. Общие контракты: [композиция](composition.md),
[данные](data.md), [проверка](checks.md), [числовая приёмка](numeric-checks.md).
Названия компонентов ниже — ключи `kit.py show/head`; параметры бери из описи.
Не добавляй герой, KPI, карту или пустой слот только ради сходства с примером.

| Рецепт | Решение | Минимальная форма данных | Исполнимая опора от корня кита |
|---|---|---|---|
| monitoring | Где требуется внимание сейчас? | Объект × период, показатель, порог и полнота | `family-mortgage.html` |
| plan-fact | Где отклонение от согласованного плана? | Факт и план одного объекта/интервала/единицы | `family-mortgage.html` |
| portfolio | Какие объекты сравнить и открыть? | Сопоставимые объекты, несколько признаков | Таблица регионов `family-mortgage.html` |
| operations | Что обработать следующим? | Запись/объект, статус, время, доступное действие | `reference-dashboard.html` |

## monitoring — наблюдение за состоянием

**Кто / решение.** Руководитель или дежурный выбирает объекты, требующие внимания.
**Вопросы.** Сколько объектов требуют внимания, какие именно, насколько отклонение
велико, есть ли объекты без оценки? Причину нельзя вывести из одного отклонения.

**Вход.** Уникальный objectId и полное имя; interval; value с единицей;
утверждённое правило status (порог и направление); updatedAt; coverage.
Геокод нужен только для географического вопроса. Источник задаёт полный список
объектов или явно обозначает границы охвата. Нулевое значение ≠ неизвестное.

**Выбор.** `tile` — ключевой счётчик, если нужен; `rank` — приоритетный короткий
список; `table` — все объекты и точные числа. `map` — только если положение
помогает решению. `chart` — только при наличии временного ряда и вопроса о динамике.
Статус без известного порога не выдумывать. Сводка/карта/таблица используют один срез.

**Сценарий.** Период + область/группа → список исключений → детали объекта →
возврат к тому же фильтру и инициатору. Локальное скрытие серии не меняет срез.
На телефоне приоритетный ответ остаётся первым, карта имеет список.

**Проверяемый ответ.** В контрольном наборе два региона, оба ниже плана; один
ровно на границе 20 п.п. недовыполнения. Фильтр СЗФО оставляет один регион,
выдано 40, выполнение 80%. Неизвестный факт даёт «Без оценки», не «По плану».

**Не подходит.** Журнал из 10 000 заявок с назначением исполнителей — operations.
Нет порогов — показывай наблюдаемые значения, а не «красные регионы» по вкусу.

## plan-fact — план и факт

**Кто / решение.** Владелец программы или бюджета выбирает объект для разбора
отклонения. Вопросы: сколько выполнено, отклонение в исходной единице и процентах,
какие объекты влияют на итог, совпадают ли период и база?

**Вход.** objectId; period; actual; plan; unit; полнота обоих значений;
версия/дата утверждения плана. Для бюджета различать план периода и общий лимит.
Процент выполнения = сумма факта / сумма плана, а не среднее процентов объектов.
Нулевой план оставляет факт видимым, но не даёт процента выполнения.

**Выбор.** `tile` для итога, `bullet-chart` для одного факта и цели, `chart`
с параллельными сериями плана/факта для динамики; `table` для отклонений.
`period-comparison` предназначен для двух периодов, не подменяет план/факт.
Не рисуй шкалу лимита, если лимита нет. План не является прогнозом.

**Сценарий.** Общий период/подразделение → сортировка отклонений → помесячные
детали → возврат. Бюджет и выдачи имеют разные единицы и отдельные шкалы.
На телефоне таблица сохраняет поля в карточках; формулы доступны в деталях.

**Проверяемый ответ.** Контрольный итог: 100 из 200, 50%; бюджет 50 из 80,
62,5%, лимит 120. В мае: 30 из 80, 37,5%. У региона без выдач факт 0 сохраняется;
при null итог не превращается в сумму известных частей без статуса неполноты.

**Не подходит.** Факт за 15 дней и план за месяц без согласованной методики
пересчёта. Не дели месячный план пополам автоматически; показывай несопоставимость.

## portfolio — сравнение объектов

**Кто / решение.** Аналитик выбирает объекты для сопоставления и углубления.
Вопросы: кто выше/ниже по выбранному показателю, какова база, что меняет фильтр?

**Вход.** Стабильный objectId, полное имя, общая дата/период, единицы и определения
сравниваемых метрик. Для долей нужны числитель и знаменатель; для взвешенного
среднего — сумма произведений и сумма весов. Не складывай остатки разных дат.
Несопоставимые охваты, валюты или определения требуют отдельной группы/статуса.

**Выбор.** `table` — основной блок нескольких признаков, `rank`/`chart` bar-h —
если нужно быстро сравнить один показатель. `select`/`search`/`pager` — по объёму.
Общий KPI нужен только при полезном вопросе об общем итоге; единая «оценка объекта»
не создаётся из нескольких показателей без утверждённой формулы.

**Сценарий.** Фильтр группы и поиск → сортировка → детали выбранного объекта.
Сортировка/страница не меняют итоги всего среза. Закрытие деталей возвращает
фокус и срез. На телефоне доступны все поля и явная сортировка.

**Проверяемый ответ.** Ставки регионов 4,5% и 8% при весах 400 и 600 дают
общую ставку 6,6%, не 6,25%. После поиска Санкт-Петербурга — 4,5%, после выбора
мая — 4%. Пагинация по одной строке не меняет итог 6,6%.

**Не подходит.** Сравнение конверсий разных когорт по одним готовым процентам.
Запроси базы; не показывай «среднюю конверсию» как среднее процентов.

## operations — операционная таблица

**Кто / решение.** Оператор выбирает следующую запись и выполняет доступное действие.
Вопросы: что требует обработки, до какого срока, кто отвечает, что доступно сейчас?

**Вход.** recordId; имя/суть; статус; timestamp с часовым поясом; ответственный и
срок, если они участвуют в решении; разрешённые действия. При агрегированных
данных явно назови единицу строки. `reference-dashboard.html` содержит
службу × день, а не отдельные заявки: не выдавай его строки за журнал инцидентов.

**Выбор.** `table`, `select`, `search`, `pager`, `modal`/`details-sidebar`;
`banner` только для нужной обратной связи. KPI/график не обязательны.
Для большого набора — серверные фильтры, итоги и страницы по data contract.

**Сценарий.** Фильтр статуса/исполнителя → строка → детали → действие → статус
результата. Во время отправки защити от повтора. Ошибка сохраняет ввод/срез,
повтор доступен; после успеха обнови данные из источника. В демо подпиши
учебность и не обещай постоянного хранения. На телефоне действия доступны из строки.

**Проверяемый ответ.** В reference-dashboard переход страниц не меняет KPI;
фильтр меняет таблицу, KPI и ряд вместе; детали соответствуют recordId, закрытие
возвращает фокус. Учебное поручение имеет обратную связь; повтор после ошибки
не сбрасывает фильтр. Проверка: `node tools/check-reference-dashboard.mjs`.

**Не подходит.** Обзор по стране без записей и реальных действий — monitoring.
Не добавляй кнопку «Назначить», если API/разрешения отсутствуют.

## Запуск и приёмка

От корня кита: `python3 tools/preview.py --port 8771`, затем
`http://127.0.0.1:8771/family-mortgage.html` или `reference-dashboard.html`.
Это существующие исполнимые композиции, не генератор по spec (#68).
Проверка контрольного набора: `node tools/check-numeric-data.mjs`, затем
`node tools/check-numeric-browser.mjs` (Chrome, Dark/Light, 390/1280).
Обычный пример открывает свои учебные данные; тест внедряет маленький fixture
через существующий load-адаптер, без изменения продовых данных или query-параметра.

Перед сдачей: вопросы → видимые ответы; точные контрольные числа; partial/no-data;
фильтр → детали → возврат; телефон/десктоп; аудит пояснений по checks.md.
Полный набор — `python3 tools/test.py`. Новые eval-сценарии являются заданиями
для будущих отдельных прогонов #70, а не доказательством качества агентов.
