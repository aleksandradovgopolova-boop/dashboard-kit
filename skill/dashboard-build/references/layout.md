# Раскладка экрана

Этот порядок — для просьбы собрать **экран целиком**. Просят один блок —
собирается один блок (SKILL.md, шаг 3).

Подробности — README кита: «Правила раскладки дашборда», «Сетка и устройства»,
«Размер виджета», «Раскладка дашборда на телефоне». Здесь — порядок решений.

## Сверху вниз — от общего к частному

1. **Поиск** (`dk-search`) — если объектов много и их ищут по имени. С датой
   данных справа.
2. **Строка фильтров** (`dk-toolbar › dk-toolbar__group`), период первым.
   Прямо на странице, не внутри виджета: фильтр в виджете действует на всё, а
   виден только там.
3. **Главная карточка** (`dk-hero`) — только если задача выделяет одно число: «25 из 89», метка
   смысла, полоса состава, чипы. **Одна на экран.**
4. **Лента** (`dk-car`) — только если нужны истории объектов, 3–7 историй.
5. **Плитки KPI** (`dk-tile`) — равноправные числа, ряд до четырёх.
6. **Графики, карта, таблица** — разбивка и детали.

Это перечень возможных блоков, не обязательный шаблон. Порядок определяется вопросами пользователя. Блок без задачи и данных не добавляют.

## Сетка

- Ширина — долей: `dk-col--quarter | third | half | two-thirds | full`, не
  числом колонок.
- Не больше 3–4 виджетов в ряду. Равная высота — `dk-grid--equal`, без обрезания содержимого.
- S (четверть) — число, подпись, тренд, спарклайн. **График с осями в четверть
  не ставят.**
- M (треть, половина) — число с графиком, список до семи, рейтинг.
- L (две трети, вся) — график с легендой, таблица, карта.

## Телефон

- Четверть становится строкой. Плитка без спарклайна встаёт по две в ряд,
  плитка со спарклайном — во всю ширину и перестраивается сама.
- Первый экран отвечает на главный вопрос пользователя. Главная карточка или график выбираются по задаче.
- Названия категорий на телефоне — `bar-h`, не столбцы.

| ✗ | ✓ |
|---|---|
| главное число внизу справа | главное — первым, слева сверху |
| действия виджета в разных местах | справа в `dk-widget__head` |
| легенда карты в другом углу | легенда — в том же блоке |
| восемь KPI-плиток подряд | до четырёх; остальное — таблица или рейтинг |

## Плотность и размер контейнера

Плотный экран получают уменьшением повторных отступов и группировкой связанных
показателей, а не уменьшением шрифта. Сохраняй размеры S и цели 44 px на таче.
Не обрамляй каждое число отдельной карточкой, если показатели читаются на общей
поверхности. Соседние карточки одного ряда имеют одинаковую высоту; содержимое
не обрезается. На узком экране меняй структуру, не масштабируй весь интерфейс.

Проверяй узкий виджет внутри широкого экрана: размер viewport не равен размеру
графика. Подписи графика сохраняют читаемый размер; сокращай число делений,
сохраняя доступ к значениям. Не растягивай SVG независимо по двум осям.
Длинное число с единицей должно помещаться либо иметь доступное полное значение.
