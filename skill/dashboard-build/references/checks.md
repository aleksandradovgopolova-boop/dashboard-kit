# Проверка и доводка

«Готово» говорится по проверкам, а не по виду. Непроверенное называется
непроверенным: «эмулятор — да, живой телефон — нет».

## 1. Проверки кита по странице

```bash
python3 <кит>/tools/check.py --page путь/к/странице.html
```

Проверяет собранную страницу правилами кита:
- **классы** — каждый `dk-*` есть в CSS (выдуманный класс — нарушение);
- **иконки** — каждая `#ti-*` есть в спрайте;
- **подключение** — нужные скрипты на месте и в верном порядке;
- **экранирование** — разметка из данных идёт через `dkEsc`;
- **таблица** — только в `dk-tablewrap`;
- **токены** — каждый `var(--x)` объявлен.

Телефонную часть — ширину, цели 44 px, вырез, шрифт полей — `--page` тоже
прогоняет в эмуляторе Chrome, если на машине есть node. Эмулятор — не живой
телефон, так и говорят.

## 2. Снимки

```bash
node <кит>/tools/snap.mjs страница.html                              # 390×844, тёмная
node <кит>/tools/snap.mjs страница.html --size 1280x900 --theme light
```

Свой Chrome без окна и фиксированный размер. **Не общая панель браузера**:
она меняет ширину, бывает скрыта и делится между сессиями. Два исполнителя
проверочных задач скилла зависли на ней насовсем. `--full` снимает страницу
целиком, но не рисует часть холстов — графики снимай экраном.

Телефон 390 × 844 и десктоп 1280 × 900, обе темы. Смотреть:
- первый экран телефона отвечает на вопрос экрана;
- нет пустых полос (растянутая плитка, фильтр во всю ширину);
- страница не шире экрана;
- в тёмной теме всё читается.

## Приёмка до первого показа

По каждому вопросу брифа: где ответ, какие данные его подтверждают, что
пользователь может сделать дальше. Проверь реальные размеры соседних
карточек, полные названия, отсутствие переполнения. Если задан один viewport,
измерь scrollHeight и innerHeight; не скрывай overflow ради результата.
Отступы не уменьшаются, чтобы вместить прежний набор блоков.

## 3. Второй проход — убрать, а не добавить

Перед сдачей пройди экран ещё раз с одним вопросом: что здесь лишнее? Лишний
блок, повтор числа, вторая главная карточка, график там, где хватит числа.
Не добавляй новое, чтобы «стало богаче».

## 4. Скажи человеку

Что собрано, какие части кита, что проверено и чем, чего нет в ките и чем
заменено. Пробелы — отдельной строкой.

## Открытые состояния и границы контейнеров

Открой меню, список выбора, подсказку и диалог. Проверь длинные варианты,
прокрутку, расположение у края viewport, выбор, Tab/Shift+Tab, Escape и возврат
фокуса. Снимок закрытой кнопки не подтверждает качество всплывающего слоя.
Проверь соседние значения вокруг используемых breakpoint, узкий виджет внутри
широкого экрана и масштаб 200%. Числа, валюты, отрицательные значения и подписи
не обрезаются. Ноль, отсутствие данных, загрузка, ошибка и неполные данные
показаны разными состояниями, если продукт умеет их определять.


## Регрессии принятого визуала

`node tools/check-composition.mjs` дополнительно проверяет семейную ипотеку
в Dark/Light на 390/900/1280 px: равные поля КПЭ, отсутствие переполнения
и пустых строк, капс Regular и равные верхний/левый отступы заголовка
даже при искусственно увеличенной до 64 px группе действий.
