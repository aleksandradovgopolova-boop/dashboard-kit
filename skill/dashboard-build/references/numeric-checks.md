# Независимая числовая приёмка

До сборки выпиши 3–6 маленьких наблюдений и ответы, которые можно проверить
вручную. Сохрани expected отдельными константами, без вызова рабочего агрегатора
или форматтера. Разные веса/знаменатели должны отличать верную формулу от
среднего процентов. Автоматическая сверка частей с итогом полезна, но сама
по себе не выявляет общую ошибку формулы.

Два уровня: MODEL — сравнение модели с константами; UI binding — сравнение
реально показанных значений с отдельными текстовыми константами. Во втором
уровне нельзя брать expected из getView(), dkFmt или результата первого уровня.
Проверяй общий срез, период, группу, объект, пересечение фильтров, пагинацию,
детали, ноль, null и пустой результат. Пропуск обязательного поля — ошибка
контракта, а не неявный ноль. Для полного списка наблюдений пропуск строки
тоже не должен выглядеть полным охватом.

## Проверяемый образец

Исходные файлы от корня кита: `tools/fixtures/numeric/mortgage-source.json`,
`mortgage-expected.json`, `comparison.json` в той же папке. Это синтетические
данные только для теста. Изолированная подстановка в существующий ипотечный
экран использует его load-адаптер, не меняет штатный набор и не отправляет данные.

| Объект / месяц | Выдано / план | Объём, млн ₽ | rateWeight, б.п.·млн ₽ | Одобрено / рассмотрено | Бюджет факт / план / лимит |
|---|---:|---:|---:|---:|---:|
| Санкт-Петербург / апрель | 10 / 20 | 100 | 60000 | 20 / 40 | 5 / 10 / 20 |
| Санкт-Петербург / май | 30 / 30 | 300 | 120000 | 30 / 60 | 15 / 20 / 30 |
| Республика Алтай / апрель | 60 / 100 | 600 | 480000 | 90 / 100 | 30 / 40 / 50 |
| Республика Алтай / май | 0 / 50 | 0 | 0 | 0 / 0 | 0 / 10 / 20 |

В этом учебном наборе лимиты относятся к месяцу и складываются; это не правило
для накопительного годового лимита реального источника.
Ручной итог: 100/200 = 50%; одобрение 140/200 = 70%; ставка
660000/1000/100 = 6,6%; бюджет 50/80 = 62,5%. Ставки объектов 4,5% и 8%
не усредняются поровну. СЗФО: 40/50 = 80%, ставка 4,5%; май: 30/80 = 37,5%,
ставка 4%. Контрольные числа и форматированные строки зафиксированы в JSON.
Дополнительный случай меняет Алтай/апрель на 180 одобрений из 200:
общий ответ 230/300 = 76,6667% (на экране 76,7%), а ошибочное среднее
региональных 50% и 90% остаётся 70%. Это ловушка для среднего процентов.

Команды: `node tools/check-numeric-data.mjs`, `node tools/check-numeric-browser.mjs`.
Обе входят в `python3 tools/test.py`; браузерная проверка не заменяется skip.

## Сопоставимость периодов

API `dkComparison(current, previous, better, comparison?)` и
`dkPeriodComparison(el, {current, previous, better, label, unit, comparison})`:

```js
comparison: {
  currentPeriod: {from:'2025-05-01', to:'2025-05-31', complete:true, sampleSize:40},
  previousPeriod: {from:'2025-04-01', to:'2025-04-30', complete:true, sampleSize:100},
  duration:'calendar-month',
  minBase:30,
  baseLabel:'заявок'
}
```

Это пример явного правила конкретной метрики, не порог для всех дашбордов.
`sampleSize` — предметная база, а не автоматически количество строк.
`complete` подтверждает закрытый период и полноту наблюдений. Поставщик
отвечает за одинаковые определения, единицы, когорты и фильтры обоих значений.
Компонент не способен установить это по двум числам.

- Метаданные отсутствуют целиком: прежний API, сопоставимость проверяет host.
  Переданы: обе пары дат и boolean complete обязательны. Частичные, неверные
  даты, неизвестная политика, дробная/отрицательная база вызывают TypeError.
- `duration:'equal'` по умолчанию требует равного числа календарных дней;
  границы включаются, даты считаются в UTC. Это не нормализация «на день».
- `calendar-month` разрешает номинальные итоги двух полных календарных месяцев,
  даже при 28/29/30/31 дне. Произвольные интервалы этим правилом не разрешены.
- `minBase` — необязательное неотрицательное целое. Если задано, обе sampleSize
  обязательны; равенство порогу допустимо. Для любой переданной базы нужен
  baseLabel. Без порога нет автоматического вывода о статистической надёжности.
- При блокировке delta/percent=null, direction=unknown, meaning=nodata,
  comparable=false. Приоритет: no-data → incomplete → duration → base → overflow.
- Previous=0: абсолютная дельта доступна, percent=null, comparable=true,
  code=zero-baseline. `better:'decrease'` делает снижение улучшением.
- period-comparison сохраняет оба значения, единицу, даты и базы видимыми;
  краткий статус — кнопка причины в dkTooltip. Нет цвета успеха/провала для
  несопоставимого изменения. Наведение/фокус/нажатие/Escape и очистка при
  update/destroy обязательны. При обновлении фокус остаётся на кнопке причины;
  после её исчезновения — на контейнере без дополнительной остановки Tab. Подключение: `kit.py head period-comparison`.

Полная семантика именованных производных метрик относится к #65. Не расширяй
ипотечную модель до неполных месяцев: она по-прежнему отклоняет их. Частичный
месяц проверяется в сравнении, пропуски измерений — в ипотечном fixture.

## Именованные определения

Для ratio-of-sums и weighted mean используй `kit.py show named-metrics` и
[контракт dkMetrics](../../../docs/named-metrics.md). Определение едино для
полей, формулы, единицы/формата, направления и дневной гранулярности.
Источник явно подтверждает полный expectedRows; отсутствие этой информации
не заменяется rows.length. Серверная страница и готовые проценты не подходят.
