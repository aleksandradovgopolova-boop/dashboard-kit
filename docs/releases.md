# Версии ресурсов и обновление потребителя

Кит поставляется набором готовых файлов. `kit-release.json` фиксирует версию,
канал, версию контракта данных и SHA-256 каждого ресурса. Общий `contentDigest`
также покрывает метаданные. Python нужен сопровождающему для проверки и
упаковки; в браузере сборка не выполняется.

Текущий пакет — кандидат `0.1.0-rc.2`. Это локальная точка проверки, а не
опубликованный стабильный релиз. Имя версии не подтверждает прохождение тестов.
Обновления выпускаются через PR; слияние, публикация и изменение потребителя
этими командами не выполняются.

## Подготовка кандидата

После изменения исходников и пересборки `kit-manifest.json`:

```sh
python3 tools/kit-release.py --write --version 0.1.0-rc.2 --channel candidate
python3 tools/kit-release.py --check
python3 tools/check-release.py
python3 tools/test.py
```

`--write` пересчитывает дескриптор. Изменение хешей рассматривается вместе с
исходниками в PR. Для уже выданного потребителю кандидата используйте следующий
номер, например `0.1.0-rc.3`; не заменяйте пакет под прежним именем.
`--check` обнаруживает изменение содержимого и добавление/удаление runtime-файлов.
`check-release.py` проверяет целостность и изоляцию пакетов; он не заменяет
браузерные проверки и приёмку подключённого источника данных.

## Создание пакета

```sh
python3 tools/kit-release.py --pack /tmp/dashboard-kit-0.1.0-rc.2
```

Родительский каталог должен существовать, конечный каталог — отсутствовать.
Даже пустой существующий каталог не перезаписывается. Файлы сначала копируются
во временный каталог и сверяются. Конечный каталог резервируется эксклюзивно,
а дескриптор переносится последним: отсутствие дескриптора означает незавершённую
упаковку. При ошибке удаляются только созданные этой операцией каталоги.

В пакет входят:

- токены и стили компонентов, каркас, стеклянное оформление;
- все `js/dk-*.js` и ресурсы, объявленные в описи;
- локальные зависимости, шрифты, иконки, PNG-фоны `assets/` и лицензии;
- опись, контракт данных и это руководство;
- `reference-dashboard.html` со своими CSS/JS и демонстрационным JSON.
- `family-mortgage.html`, учебная предметная модель, наблюдения и ресурсы
  карты; аналитический потребитель без команд записи.
- необязательный `tools/reference-server.py` и руководство для локальной
  проверки POST API, серверной пагинации и демонстрационных поручений.

История Git, настройки AI Ops и пользовательские данные в пакет не включаются.
Эталон демонстрационный; для его загрузки данных необходим HTTP-сервер.
Для режима API можно запустить включённый локальный сервер: Python нужен
только этому демонстрационному инструменту, не страницам в браузере.

## Фиксация в приложении

Потребитель хранит версию и полный `sha256:…` из вывода принятого кандидата
в собственном lock-файле под контролем версий. Проверять нужно именно по этому
внешнему значению, а не читать ожидаемый хеш из проверяемого пакета:

```sh
python3 /path/to/dashboard-kit/tools/kit-release.py \
  --verify /path/to/application/vendor/dashboard-kit/0.1.0-rc.2 \
  --expect sha256:FULL_DIGEST_FROM_REVIEWED_CONSUMER_LOCK
```

Замените пример полного digest фактическими 64 шестнадцатеричными символами.
Без `--expect` команда не подтверждает пакет. Изменённые, отсутствующие,
лишние файлы, символьные ссылки и пути за пределы пакета отклоняются.
Хеш подтверждает соответствие одобренному содержимому; это не цифровая подпись
и не свидетельство безопасности исходного кода.

Приложение подключает CSS и JavaScript из одной версии. Порядок берётся из
описи: `dk-theme` первым, `dk-util` до зависящих компонентов; стили —
primitives → semantic → components. Не смешивайте файлы двух версий и не
используйте изменяемый адрес `latest` в production.

## Обновление и откат

1. Установить новый пакет в соседнюю папку с новым номером; сверить внешний pin.
2. Проверить эталон и реальные сценарии приложения: данные, фильтры, ошибки,
   темы, повторное открытие, доступность и целевые устройства.
3. В PR потребителя изменить версию, digest и все пути ресурсов вместе.
4. Сохранять предыдущий пакет и его pin. Для отката вернуть прежнюю запись
   и пути ресурсов, затем повторить проверку сценариев.

Переключение версии выполняет хост-приложение. Для уже открытой страницы нужен
полный переход/перезагрузка: горячая подмена библиотек не поддерживается.
Серверные схемы и пользовательские данные требуют собственного плана миграции;
возврат CSS/JS не откатывает изменения базы данных.

## Совместимость

`dataContractVersion: 1` фиксирует форму данных, описанную в
[dashboard-data.md](dashboard-data.md). Неизвестная версия отклоняется.
Ломающие изменения контракта требуют новой версии контракта и миграции
адаптера. Для релиза документируйте изменения API, контрактов, токенов и
поведения, затрагивающие потребителей. Стабильный канал допускается после
приёмки и выпуска через PR; флаг `--channel stable` сам по себе этого не делает.
