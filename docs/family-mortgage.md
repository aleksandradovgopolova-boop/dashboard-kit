# Семейная ипотека: первый аналитический потребитель

Текущая композиция и ограничения сверены с Dashboard Kit 2.0:
[требования](../DESIGN-UX-ACCESSIBILITY.md), [проверка экрана](../REVIEW.md).
Легенда карты выделяет категорию локально и сохраняет общий фильтр региона/
округа; остальные показатели при этом не пересчитываются. География не
перестраивается. Единица измерения остаётся в подсказке, не под легендой.
На планшете карта занимает строку; мобильный читаемый географический обзор
ещё не завершён. Данные остаются учебными.


Владелец выбрал этот экран для проверки кита перед тиражированием:
сейчас **учебные данные и только анализ** — сравнение, детали региона,
выгрузка. Поручения и изменение статусов в этот сценарий не входят.
Страница не описывает реальные условия кредитования или результаты программы.

## Открыть

Из корня репозитория:

```sh
python3 tools/reference-server.py --port 8772
```

Затем открыть `http://127.0.0.1:8772/family-mortgage.html`.
Этот экран загружает локальный учебный JSON. Сервер здесь раздаёт файлы,
а не выполняет расчёты ипотечных показателей. Можно использовать обычный
HTTP-сервер. Открытие HTML через `file:` не подходит для загрузки JSON и карты.

## Оформление

Общий переключатель Glass / Dark / Light; стекло сохраняется во всех стилях.
Материал берётся из css/glass.css, отдельной копии у экрана нет.

## Сценарий и области действия

1. Выбрать весь период или полный месяц, округ, поиск по названию региона.
2. Сопоставить KPI, число отстающих регионов, карту, рейтинг и месячные ряды.
3. Открыть регион из рейтинга, таблицы или карты. В деталях — тот же период,
   факт и план по месяцам, объём, ставка и решения по заявкам.
4. Скачать CSV всех регионов выбранного среза, включая источник, даты,
   единицы и признак `demo`. Пустые значения в CSV означают отсутствие данных.

Все фильтры действуют на все аналитические блоки. Сортировка меняет порядок
всего среза перед пагинацией, а рейтинг всегда показывает максимальное
недовыполнение. Переключение страницы таблицы не меняет KPI и графики.
Карта использует постоянную количественную шкалу 0–100 п.п.; регионы вне
среза приглушены, а отсутствие данных обозначено отдельно.

В адресе сохраняются `fm-month`, `fm-district`, `fm-search`, `fm-sort`,
`fm-page`. Назад/вперёд восстанавливают срез. Пустой результат скрывает старые
значения. Ошибка загрузки предлагает повтор. Страница вне диапазона
сохраняет общие итоги и предлагает переход на первую страницу.

## Один набор вместо независимых макетных чисел

`data/family-mortgage-observations.json` содержит 534 вымышленных наблюдения:
89 регионов × 6 полных месяцев, апрель–сентябрь 2025. Региональные идентификаторы
и названия взяты из существующего примера; все числовые наблюдения учебные.
Дата версии источника — 1 октября 2025; дата открытия страницы её не меняет.
Старый `data/family-mortgage-demo.json` сохранён как исторический макет;
обновлённый экран его не загружает.

Гранулярность — регион × месяц. Дата первого числа обозначает весь полный
месяц, а не дневное наблюдение. Все месяцы каждого региона присутствуют;
неизвестное значение записывается явно как `null`. Модель отклоняет неполную
решётку, дубликаты, смешанные единицы и несовместимые определения.

| Показатель | Формула для выбранного среза |
|---|---|
| Выдано / план кредитов | Суммы `issued` / `issuedPlan` |
| Объём выдач | Сумма `volume`, в источнике млн ₽; на экране млрд ₽ |
| Выполнение плана | `sum(issued) / sum(issuedPlan) × 100` |
| Недовыполнение | `max(0, 100 − выполнение плана)`, п.п. |
| Средняя ставка | `sum(rateWeight) / sum(volume) / 100`, % |
| Одобрение | `sum(approved) / sum(applied) × 100`, % |
| Бюджет | Суммы месячных расходов, планов и лимитов; выполнение = расходы / план × 100 |

`rateWeight` — ставка в базисных пунктах, умноженная на объём в млн ₽.
`applied` в этом контракте означает **рассмотренные заявки**, а `approved` —
одобренные из той же завершённой когорты решений. Это не количество поданных
заявок за месяц. Для реального источника такое соответствие нужно подтвердить.
Бюджетные значения — месячные потоки, не накопительные снимки.

Учебная классификация из неокруглённого недовыполнения: 0 — план выполнен;
больше 0 и меньше 20 п.п. — отставание; от 20 п.п. — сильное отставание.
Округа считаются отношением сумм факта и плана, не средним региональных
процентов. Эти пороги не являются нормативом программы.

Ноль — известное измерение. Нулевой знаменатель даёт `null`. Если хотя бы
одно значение слагаемого неизвестно, итог и зависимая доля не показываются
как полные: модель возвращает `null` и покрытие `coverage`. Регион без
полного факта или плана, а также с нулевым планом выделяется в число «нет данных»; он не считается
выполнившим план. Выводы описывают наблюдения, причинность не заявляется.

## Граница кита и приложения

- `js/dk-dashboard.js` — общий контракт, ограниченная HTTP-загрузка,
  отмена, таймаут 15 секунд для этого экрана, повтор и уничтожение сессии.
- `js/family-mortgage-data.js` — учебная предметная модель. Проверяет
  аддитивные наблюдения, считает отношения сумм и группировки. Принимает
  только источник `demo`, чтобы заменой URL нельзя было выдать учебную
  методику за производственную.
- `js/family-mortgage.js` — адаптер экрана: фильтры, URL, компоненты,
  детализация и экспорт. При уничтожении освобождает загрузки, обработчики,
  графики и карту. Общие компоненты не знают ипотечных формул.

```js
const screen = familyMortgageDashboard(root, {
  url: false, // адресом управляет хост, если экран встроен
  load: async ({signal}) => {
    // Вернуть полный небольшой учебный snapshot; поддержать signal.
    return fixture;
  }
});
screen.setQuery({district: 'ЦФО', month: '2025-09'});
screen.getView();
screen.destroy();
```

`root` — корень существующей разметки этого экрана. Несколько экземпляров с
одинаковыми HTML ID на одной странице не поддерживаются. Повторный mount
того же корня уничтожает предыдущий экземпляр. Параметр `load` возвращает
данные, а не принимает команды записи. Фреймворк не требуется; хост с
React/Vue может вызывать этот lifecycle из своей обёртки.

Текущие 534 агрегированных наблюдения загружаются целиком, фильтрация
локальная. Для десятков тысяч первичных записей нужна отдельная серверная
реализация именно ипотечного среза: группировки по регионам/месяцам,
взвешенные суммы, согласованный snapshot и стабильная сортировка до
пагинации. Общий учебный `/api/dashboard` такой реализацией не является.
Реальное API, права и интеграция в ИИ-среду ещё не подключены.

## Проверка

`node tools/check-family-mortgage-data.mjs` — 12 сценариев: сверка итогов
с регионами и месяцами, фильтры, детали, сортировка до страниц, взвешенные
отношения, пропуски, нулевые знаменатели и отклонение неверных данных.

`node tools/check-family-mortgage.mjs` — браузерная приёмка: две темы,
ширины 320/390/768/1280, фильтры, история, детали/фокус, пустой срез,
ошибка/повтор и повторный mount. Включена в `python3 tools/test.py`.
Нужны разрешённый локальный сервер и Chrome. В текущей сессии браузерная
приёмка не выполнена из-за ограничений окружения; это не PASS.
