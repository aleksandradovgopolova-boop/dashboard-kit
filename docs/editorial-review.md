# Редакционная приёмка рабочего экрана

Выполняется отдельно от машинной проверки. Ноль найденных точек не доказывает
лаконичность; удаление конечной точки не превращает объяснение в полезный статус.

Для каждой постоянно видимой подписи зафиксируйте:

| Текст / место | Роль | Решение |
|---|---|---|
| Название показателя, единица, период, легенда, краткий статус | Необходимый ответ или контекст данных | Оставить видимым |
| Описание реальной заявки/аварии | Содержательные данные объекта | Сохранить, не подменять общим пояснением |
| Повтор названия/фильтра, инструкция очевидного клика | Не даёт нового ответа | Удалить |
| Определение, формула, методика, источник | Дополнительное объяснение | Один обнаруживаемый вход по запросу |
| Ошибка/пустой результат | Состояние и следующий доступный шаг | Сохранить необходимое, убрать повтор кнопки |

Проверьте обзор, фильтрованный срез, пустой результат, partial и реальные детали.
Основной ответ должен читаться без открытия подсказки. Короткий неинтерактивный
текст — Tooltip; ссылки/настройки — Popover/детали. Клавиатура, Escape, touch,
повторное открытие и очистка после восстановления данных проверяются отдельно.
Учебный каталог и согласованный hero не объявляются рабочим обзором.

## Что проверяет машина

Область задаётся `data-dk-screen=overview|operations|detail|catalog`.
Лимит семи применяется только к overview: самостоятельный KPI героя входит
в число, label/value внутри той же tile не удваивают его. Скрытый loading
не позволяет спрятать восьмой запланированный KPI; dialog/detail не входят
в счёт основного обзора. Для динамических примеров добавлена runtime-проверка.
Компилятор screen-spec требует kind и проверяет состав до генерации.

Структурная проверка ловит явные пустые колонки, резервирование слота,
невидимый сброс с занимаемым местом и незарегистрированный page.css.
Hidden/display:none и закрытые dialog не считаются занимающими место;
открытый detail проверяется. Статический разбор inline styles не вычисляет
произвольный CSS cascade. Отсутствие scope значит, что KPI-политика не применялась,
а не что смысл экрана был автоматически принят.

`python3 tools/check-screen-policy.py --page PATH --json` возвращает структурные
ошибки и editorialReview:required. Эти же проверки включены в check.py.
Positive/negative fixtures проверяются командой без --page; существующие
check-composition и example-shell сохранены.
