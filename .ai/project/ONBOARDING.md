## Что блокирует
required_now: назначить реальный приватный security-contact и подтвердить supported versions, чтобы политика раскрытия стала рабочей. Для документационного PR это открытая неопределённость, не повод выдумать контакт.
required_before_next_change: для реальных данных — источники, единицы, права и классификация; для production — окружение/оператор/процедура.
can_reconstruct: динамические смысловые цвета и браузерные регрессии из плана; не требуют создания нового фреймворка.
opportunistic: baseline исследования и product adoption.

## Следующая работа
./ai-ops next рекомендует динамические смысловые цвета из существующего плана. Перед исследованием согласовать роль/сценарии/KPI; рекомендации метрик не утверждённые цели.

## Вопросы владельцу одним пакетом
1. Кто основной пользователь библиотеки и готового дашборда; какие 2–3 задачи и ближайший результат приоритетны?
2. Кто владеет продуктом, безопасностью/QA/delivery; какие реальные аккаунты назначить CODEOWNERS? Какой приватный канал уязвимостей, сроки ответа и поддерживаемые версии?
3. Где production и кто оператор; есть ли чувствительные реальные данные и ограничения передачи AI-провайдерам?
4. Какой измеримый успех выбрать из ProductMetrics/MetricCatalog, кто измеряет и когда снять baseline?
Остальные границы уже заданы AGENTS: managed не править, Kit stable через PR, без automerge/публикации; не переспрашивать их.
