# dashboard-kit

Библиотека для быстрой сборки дашбордов. Один источник правды по цвету, шрифту,
ритму, форме и поведению блоков.

Сборки нет и не будет: подключается локальными CSS/JS-файлами, работает офлайн,
открывается двойным кликом. Это осознанный выбор — так же устроена витрина
мониторинга ЖКХ, и это единственное, что команда умеет деплоить без лишних шагов.

## Посмотреть

Открой `showcase.html` — там все блоки во всех состояниях и обе темы. Акцент
ставится один раз на продукт атрибутом `data-accent` на корне (`blue`, `violet`,
`indigo`); переключателя нет намеренно.

## Подключить

Порядок здесь не произвольный. Два файла стоят на своих местах не по вкусу:

- **`js/dk-theme.js` — первым и без `defer`.** Он ставит атрибут темы до первой
  отрисовки; отложи его, и человек со светлой темой увидит тёмную страницу и
  вспышку. Это единственный файл кита, которому можно блокировать разбор.
- **`js/dk-util.js` — до всех остальных `dk-*`.** В нём общее экранирование, и
  компоненты без него падают намеренно: разметка, молча собранная без
  экранирования, хуже ошибки.

```html
<script src="js/dk-theme.js"></script>

<link rel="stylesheet" href="css/tokens.primitives.css">
<link rel="stylesheet" href="css/tokens.semantic.css">
<link rel="stylesheet" href="css/components.css">

<script src="js/dk-util.js"></script>
<script src="js/dk-icons.js" defer></script>

<!-- только если на странице есть графики ИЛИ карта: карта рисуется тем же
     движком. Нет ни того ни другого — не подключать: это 1148 КБ. -->
<script src="vendor/echarts.min.js" defer></script>
<script src="js/dk-chart-theme.js" defer></script>
<script src="js/dk-charts.js" defer></script>

<!-- только если на странице есть выпадающий список -->
<script src="js/dk-select.js" defer></script>

<!-- только если на странице есть выбор периода -->
<link rel="stylesheet" href="vendor/air-datepicker.css">
<script src="vendor/air-datepicker.js"></script>
<script src="js/dk-period.js"></script>

<!-- только если кит рисует всю страницу: меню и шапку -->
<link rel="stylesheet" href="css/chrome.css">
<script src="js/dk-chrome.js" defer></script>

<!-- только если на странице есть модальное окно -->
<script src="js/dk-modal.js" defer></script>

<!-- только если на странице есть календарь событий -->
<script src="js/dk-calendar.js" defer></script>

<!-- только если на странице есть постраничная навигация -->
<script src="js/dk-pager.js" defer></script>

<!-- только если в таблице выбирают строки или сортируют -->
<script src="js/dk-table.js" defer></script>

<!-- только если на странице есть форма -->
<script src="js/dk-form.js" defer></script>

<!-- только если на странице есть карта регионов -->
<script src="js/dk-map.js" defer></script>

<!-- только если на странице есть лента карточек -->
<script src="js/dk-car.js" defer></script>

<!-- только если на странице есть уведомления или полоса доступности -->
<script src="js/dk-notify.js" defer></script>
<script src="js/dk-uptime.js" defer></script>
```

Стиль календаря подключается **до** `components.css`: наши правила перекрывают
его, а не наоборот.

Порядок важен: примитивы → семантика → компоненты. Каждый слой читает только предыдущий.

```html
<html lang="ru" class="dk-root" data-theme="dark" data-accent="blue">
  <body class="dk-page">
    <div class="dk-wrap">…</div>
  </body>
</html>
```

`data-theme` — `dark` или `light`. `data-accent` — `blue`, `violet`, `indigo`.
Меняются независимо друг от друга.

## Границы кита: .dk-root и .dk-page

Всё, что кит о себе объявляет — токены, гарнитура, цвет текста, — объявлено на
классе `.dk-root`. На `:root` кит не пишет ничего, и это не педантизм: из 258
токенов 166 названы короткими именами вроде `--bg`, `--ink`, `--surface`,
`--space-4`, и на корне документа они столкнулись бы с чужой дизайн-системой в
обе стороны и молча.

**Контракт: класс `.dk-root` и атрибуты `data-theme` / `data-accent` стоят на
одном и том же элементе.**

```html
<!-- своя страница кита -->
<html class="dk-root" data-theme="dark" data-accent="blue">
  <body class="dk-page"> … </body>
</html>

<!-- внутри чужого приложения: .dk-page не нужен -->
<div class="dk-root" data-theme="dark">
  <div class="dk-widget"> … </div>
</div>
```

`.dk-page` — это отдельное заявление: «кит владеет всей страницей». Он обнуляет
поля документа и красит фон. Встроенному киту он не нужен и вреден: закрашивать
фон хозяина не наше дело.

Проверить встраивание можно на [embed.html](embed.html) — это намеренно
враждебная чужая страница: хозяин объявляет свои `--bg`, `--ink`, `--surface`,
`--brand` с теми же именами, ставит Georgia и охряный фон, а кит живёт внутри
неё в рамке. Ни одна переменная не должна протечь ни в одну сторону.

## Чем кит весит

Честные числа, а не «он маленький»:

| что | размер |
|---|---|
| CSS кита (токены, компоненты, каркас) | 338 КиБ исходников; документационные стили отдельно |
| JS кита (dk-*.js) | 332 КиБ исходников; optional файлы подключаются по необходимости |
| шрифты | до 235 КБ: восемь файлов Golos, кириллица и латиница на четыре начертания; браузер грузит только те, что стоят на странице |
| ECharts | 650 КБ (221 КБ со сжатием при передаче) — урезанная сборка, только на страницах с графиком или картой |

Сборки у кита нет намеренно: он читается как текст, и комментарии в нём — не
довесок, а половина содержания, потому что каждое правило объясняет, из-за
какой ошибки оно появилось. Цена этого решения — те самые проценты в таблице,
и платит их хозяин страницы на каждой загрузке. Если это неприемлемо, сжатие
ставится на стороне сервера: `gzip` съедает комментарии почти целиком.

## Размеры считаются вместе с полями

Внутри `.dk-root` у всех элементов `box-sizing: border-box`: ширина и высота
включают поля и рамку. Без этого `width: 100%` и `height: 100%` считались без
полей, и элементы вылезали из своих мест: меню фильтра на 16 px шире кнопки,
виджет на 48 px ниже колонки, боковое меню выше экрана.

- **Кроме ячеек таблицы.** Их ширину считает раскладка таблицы, и проценты
  колонок в разметке написаны под прежний счёт.
- **Размеры хозяина кит не трогает**: правило действует только внутри
  `.dk-root`.
- При включении правила все размеры `dk-*` на всех страницах сняты до и
  после; каждое изменение разобрано (DECISIONS.md, п. 11).

## Два правила

**Ни обводок, ни теней.** Блок отделяется от соседа поверхностью и воздухом.
Виджет светлее фона в обеих темах — ступень около 1.18:1 в тёмной и 1.15 в
светлой (выше в светлой не выходит: до белого мало места, и попытка растянуть
делает страницу серой). Этого достаточно,
чтобы край читался, и мало, чтобы он лез в глаза. Поля и кнопки залиты и потому
читаются как нажимаемые без рамки.

Исключений шесть, и все функциональные:

- **тень у всплывающих слоёв** — меню, подсказка, модальное окно. Слой, лежащий
  поверх содержимого, обязан отделяться от того, что под ним: без этого меню
  сливается с текстом страницы. Это разделение слоёв, а не украшение;
- кольцо фокуса с клавиатуры — появляется только при навигации табом и исчезает
  при работе мышью, так что шума не создаёт. Без него человек, работающий без
  мыши, теряет своё место на странице. **Не удалять.**
- `dk-table--zebra` и `dk-table--ruled` — для плотных таблиц, где взгляд теряет
  строку на длинной дистанции. Включаются вручную, по умолчанию выключены;
- **пилюли фильтров на доске страницы** — тонкая кромка и мягкая тень
  (`--edge-float`, `--elev-float`). На тёмной доске пилюля без них читалась
  дыркой, а не кнопкой. Внутри виджета та же пилюля плоская;
- **строка поиска и нижняя панель разделов** — кромка и глубокая тень
  (`--elev-bar`): поиск лежит на доске, панель — поверх содержимого;
- **главная карточка экрана** (`dk-hero`) — глубокая тень и оттенок по смыслу
  (`--elev-hero`, `--accent`). Она одна на экран и отвечает на «куда смотреть
  первым». Оттенок — только смысловым цветом, никогда брендом.

Последние три исключения — решение владельца кита 29.09.2026 по живому
мониторингу, на который равняется телефон (DECISIONS.md, п. 8). Обычные
виджеты по-прежнему без рамок; их мягкий подъём (`--elev-widget`) описан в
токенах.

**Смысловые цвета акцентом не управляются.** Красный всегда означает «высокий
риск», зелёный — «низкий». Если сделать акцент красным, читатель начнёт принимать
кнопку за тревогу, и дашборд станет врать. Поэтому в наборе акцентов нет ни
красного, ни жёлтого, ни зелёного.

## Правила правки

Перед коммитом:

```bash
python3 tools/check.py
```

Скрипт проверяет двадцать пять вещей (полный список с причинами — в шапке
`tools/check.py`; последняя, ТЕЛЕФОН, открывает страницы в Chrome и идёт
полминуты, `--fast` её пропускает), среди них: компоненты не лезут в примитивы через голову
семантики; цвет нигде не задан значением; каждый `var(--x)` где-то объявлен;
у входных параметров есть значения по умолчанию; **все размеры в пикселях
чётные** — интерфейс стоит на сетке в 2 px (шкала отступов 2 · 4 · 6 · 8 ·
10 · 14 · 18 · 24 · 36), и нечётное значение с неё сваливается. Раньше здесь
было написано «4 px», что шкале не соответствовало; переход на сетку 4 — открытый
вопрос в DECISIONS.md, пункт 5; текст читается на своей поверхности в обеих темах; палитра серий
не менялась без повторной проверки различимости; стили наведения закрыты от
тача — правило с `:hover` обязано лежать внутри `@media (hover: hover)`;
**соседние поверхности различимы**; **акцент не путается со смыслом, в том
числе при дальтонизме**; **подпись и силуэт кнопки читаются на всех акцентах**; **все ступени шкалы
карты видны на своей доске**; **в урезанном ECharts ровно то, что просит код**; **график и карта не
создаются в контейнере без размера** — там карта и санкей падают; **управление
тише данных** — акцент только у основной кнопки, фокуса и ссылок, выбранное
состояние серое (`--control-on`, `--control-soft`); **страницы компонентов собраны
скриптом и все одиннадцать блоков на месте**; **опись кита для скилла совпадает
с кодом**; **каждый класс кита в разметке, скриптах и примерах README есть в CSS**;
**иконки приложения и фавикон на месте и нужного размера**.

Страница, собранная вне кита, проверяется теми же правилами, что проверяются
по тексту: `python3 tools/check.py --page путь/к/странице.html`. Это классы,
иконки, подключение и его порядок, экранирование, таблицы и токены. Телефонную
часть для чужой страницы кит не запускает.

Новая страница компонента — это запись в `tools/component_pages/*.py` и
`python3 tools/build-component-pages.py`. Пустой блок генератор не соберёт: если
сказать нечего, это пишется словами.

После правки страниц компонентов, CSS, скриптов кита или
`tools/manifest_parts.py` пересобери опись: `python3 tools/build-manifest.py`.
Новый класс должен кому-то принадлежать. Для блока со страницей префикс
пишется в `tokens` страницы, для прочего — в `tools/manifest_parts.py`. Иначе
проверка МАНИФЕСТ не пропустит: скилл сборки дашбордов о классе не узнает.

Новый тип графика или новая настройка ECharts — это правка
`vendor/echarts.modules.json` и `python3 tools/build-echarts.py` (нужны node,
npm и сеть на время сборки). Без этого проверка ДВИЖОК не пропустит: урезанная
сборка без нужного модуля оставляет график пустым или раскладывает его иначе,
и в консоли об этом ни слова. После пересборки — сравнение с полным движком в
браузере, см. REVIEW.md, «Урезанный ECharts».

Возвращает 1 при нарушении — можно вешать на хук или в CI.

**Новое значение цвета идёт в примитивы, а не в компонент.** Если хочется
вписать `#166FF2` в `components.css` — значит, не хватает семантического
токена. Заведи его.

**Новая иконка** — вписать имя с [tabler.io/icons](https://tabler.io/icons)
в список `ICONS` и запустить:

```bash
python3 tools/build-icons.py
```

Набор держим маленьким намеренно: в Tabler пять тысяч иконок, дашборду нужно
два десятка. Тянуть всё ради двадцати — лишний вес и лишняя внешняя зависимость.

## Правила раскладки дашборда

Правила, а не вкус. Каждое отвечает на вопрос «почему», иначе его нарушат при
первом же неудобстве.

### Расположение

**Сверху вниз — от общего к частному.** Сводка, потом разбивка, потом детали и
лента. Дашборд читают как ответ на вопрос «как дела?», и только потом
«а почему так».

**Главное — в левом верхнем углу.** Взгляд начинает оттуда. Если главное число
оказалось внизу справа, его увидят последним или не увидят вовсе.

**Фильтры — одной строкой над содержимым**, а не внутри виджетов. Человек
должен видеть все действующие условия сразу: фильтр, спрятанный в одном из
виджетов, действует на всё, а заметен только там.

**Не больше трёх-четырёх виджетов в ряду** на десктопе. Дальше каждый становится
слишком узким, чтобы в нём что-то прочитать.

**Действия виджета — справа в его шапке**, всегда в одном месте. Человек не
должен искать кнопку обновления заново в каждом блоке.

**Связанное стоит рядом.** Карта и её легенда — один блок. Легенда, уехавшая в
другой угол, перестаёт быть легендой.

### Выравнивание

**Числа по правому краю, текст по левому.** Числа сравнивают по разрядам, и для
этого они должны стоять друг под другом; текст читают с начала строки. Плюс
табличные цифры — иначе колонка дёргается при обновлении.

**Один левый край на всю колонку.** Заголовок виджета, подпись и содержимое
начинаются с одной вертикали. Сдвиг на пару пикселей заметен, даже когда его не
могут объяснить.

**Подпись и значение — по базовой линии**, а не по центру блока. Крупное число
рядом с мелкой подписью, выровненное по центру, всегда выглядит съехавшим.

**Не бывает «почти выровнено».** Либо элементы на одной линии, либо это явно
разные группы с явно разным отступом. Промежуточное состояние читается как
ошибка вёрстки.

### Отступы

Главный закон: **расстояние — это связь.** Люди группируют то, что стоит ближе.
Рамок у нас нет, и блок делает блоком именно расстояние вокруг него.

Отсюда практическое правило: расстояние **внутри** группы заметно меньше
расстояния **до соседней** группы. Если они равны, две группы читаются как одна,
и человек ищет смысл там, где его нет.

Четыре имени вместо девяти чисел — чтобы не выбирать каждый раз заново:

| Токен | Значение | Для чего |
|---|---|---|
| `--gap-tight` | 8 | внутри одной вещи: значок и подпись |
| `--gap-inline` | 10 | между вещами одной группы |
| `--gap-group` | 14 | между группами внутри виджета |
| `--gap-section` | 18 | заголовок и содержимое, ряды виджетов |
| `--pad-widget` | 18 | внутреннее поле виджета |

Внутреннее поле виджета заведомо больше внутренних зазоров: иначе содержимое
липнет к краю и виджет теряет собственные границы — а границ у нас нет, их роль
играет как раз это поле.

Отступ берётся только из шкалы. `15px` «на глаз» — это начало конца: через месяц
их будет двадцать разных, и ни один нельзя будет поменять централизованно.

## Сетка и устройства

Три точки перелома, и у каждой свой смысл, а не просто ширина:

| Устройство | Ширина | Колонок | Что меняется |
|---|---|---|---|
| Мобилка | до 768 | 4 | одна колонка |
| Планшет | 768–1199 | 8 | две колонки, боковая уходит вниз |
| Десктоп | от 1200 | 12 | полный дашборд с боковой колонкой |

12 колонок на десктопе — потому что 12 делится на 2, 3, 4 и 6: половина, треть,
четверть и шестая часть получаются без остатка.

**Ширина виджета задаётся долей, а не числом колонок:**

```html
<div class="dk-grid">
  <div class="dk-col--half">…</div>
  <div class="dk-col--quarter">…</div>
  <div class="dk-col--quarter">…</div>
</div>
```

«Половина» остаётся половиной на всех устройствах, а «четверть» на мобилке
честно становится целой строкой — четверть от четырёх колонок нечитаема. Если
бы ширина задавалась числом колонок, разметку пришлось бы переписывать на
каждой точке перелома.

Доли: `--quarter`, `--third`, `--half`, `--two-thirds`, `--full`.

Для раскладки «основное плюс боковая колонка» — как в витрине мониторинга, где
слева карта, а справа сводка и лента — есть `dk-layout`. Для ряда одинаковых
плиток, которые сами решают, сколько влезет в строку, — `dk-grid--even`.

**Под пальцем элементы управления вырастают до 44 пикселей** — на телефоне,
на планшете и на телефоне боком. Решает указатель (`pointer: coarse`), а не
ширина: телефон боком шире 767 px, и правило «по ширине» отдавало ему кнопки
в 28. Палец крупнее курсора и точнее не становится: цель обязана расти, как бы
мелко элемент ни выглядел на макете. Таблица не ломается и не прячет колонки,
а прокручивается вбок — спрятанная колонка читается как отсутствующие данные.
Подробности — «Телефон и приложения».

⚠️ Сами точки перелома в медиазапросах написаны числом: CSS не умеет подставлять
переменные в `@media`. Значения продублированы в токенах, чтобы их было где
прочитать, но менять придётся в двух местах.

## Размер виджета

S, M и L — не три вкуса, а три пролёта сетки. Размер выбирается не тем, сколько
хочется показать, а тем, сколько влезает, оставаясь читаемым.

| Размер | Пролёт | Что туда кладут |
|---|---|---|
| **S** | четверть колонки | одно число, подпись, тренд, спарклайн |
| **M** | треть или половина | число с графиком, список до семи строк, рейтинг |
| **L** | две трети или вся ширина | график с легендой, таблица, карта |

**График с осями в четверти колонки — это подписи мельче десяти пикселей.**
Такой график притворяется точным, будучи нечитаемым. Поэтому в размер S идёт
число и форма — спарклайн без осей, — а сравнение многих значений живёт в L,
где на него есть ширина.

Разметка у всех трёх одна и та же — `dk-widget`. Отличается только плотность
набивки: у плитки в четверть колонки поле в 18 съедает пятую часть ширины,
поэтому для неё есть `dk-widget--s`. Больше ничего заводить не нужно —
остальное делает сетка.

```html
<div class="dk-col--quarter">
  <div class="dk-widget dk-widget--s dk-tile" style="--accent:var(--crit)">
    <div class="dk-tile__head">
      <span class="dk-tile__icon"><svg class="dk-i dk-i--sm"><use href="#ti-alert-triangle"/></svg></span>
      <span class="dk-tile__label">Аварии за сутки</span>
    </div>
    <div class="dk-tile__row">
      <span class="dk-metric-lg">23</span>
      <span class="dk-trend" style="--accent:var(--crit)">+18%</span>
    </div>
    <div class="dk-chart dk-chart--spark" id="t1"></div>
  </div>
</div>
```

### Спарклайн

```js
dkChart(el, { type: 'spark', categories: days, series: [{ name: 'Аварии', data: [...] }] });
```

Спарклайн — это форма, а не график: он отвечает на вопрос «куда идёт», а на
вопрос «сколько» отвечает число рядом. Поэтому ни осей, ни сетки, ни легенды.
Серия ровно одна: вторую на такой высоте не отличить от первой.

Шкала здесь единственный раз идёт не от нуля — на высоте в сорок восемь
пикселей нулевая база расплющивает любое изменение в прямую, то есть прячет
ровно то, ради чего спарклайн и рисуют.

Цвет — серии, а не состояния, даже на тревожной плитке: что всё плохо, уже
сказано числом, значком и цветом тренда, а линия отвечает за направление.

### Виджет-список

Последние события, ближайшие работы, верх списка чего угодно. От рейтинга
(`dk-rank`) отличается второй строкой — «где и когда»; без неё список событий
приходится дополнять всплывающей подсказкой, а подсказки не видно на планшете.

```html
<div class="dk-list">
  <button class="dk-list__row" style="--accent:var(--crit)">
    <span class="dk-list__icon">…</span>
    <span class="dk-list__text">
      <span class="dk-list__name">Прорыв теплотрассы</span>
      <span class="dk-list__sub">Новосибирск · 14:20</span>
    </span>
    <span class="dk-list__v">1 240 чел.</span>
  </button>
  <button class="dk-list__more">Показать все</button>
</div>
```

Длина ограничена сознательно: список длиннее семи строк — это таблица, и
показывать её надо таблицей, с сортировкой и прокруткой. «Показать все» стоит
под списком, а не в шапке: человек доходит до конца и там понимает, что список
неполон.

## Каркас страницы

**Этот слой необязателен.** Кит начинался как набор блоков, которые встраивают
в чужую страницу — так он и работает в витрине мониторинга ЖКХ, где меню и
шапка уже свои. Не подключили `chrome.css` — ничего не изменилось. Подключили —
получили отдельный дашборд целиком. Каркас не трогает ни один класс из
`components.css`, и `dk-wrap` с сеткой ведут себя одинаково внутри `dk-app` и
снаружи.

Собранный пример — `dashboard.html`.

```html
<body class="dk-page">
  <a class="dk-skip" href="#main">К содержимому</a>

  <div class="dk-app" data-nav="closed">
    <aside class="dk-side">
      <div class="dk-side__head">…название, кнопка свернуть…</div>
      <nav class="dk-side__nav" aria-label="Разделы">
        <div class="dk-side__group">Обзор</div>
        <a class="dk-side__item" href="#" aria-current="page">
          <svg class="dk-i dk-i--sm"><use href="#ti-layout-grid"/></svg>
          <span class="dk-side__label">Сводка</span>
          <span class="dk-side__n">23</span>
        </a>
      </nav>
      <div class="dk-side__foot">…настройки, кто вошёл…</div>
    </aside>

    <div class="dk-main">
      <header class="dk-top">…путь, заголовок, инструменты…</header>
      <main class="dk-content" id="main"><div class="dk-wrap">…</div></main>
    </div>
  </div>
</body>
```

**Меню слева, а не сверху.** Разделов у дашборда больше, чем помещается в
строку, и их число растёт: список вниз растёт бесконечно, строка — нет. Верхнее
меню на седьмом разделе превращается в «Ещё ▾», то есть прячет половину
продукта за лишним щелчком.

**Шапка липкая, меню прокручивается само.** Дашборд длинный. Уехавшая вверх
шапка уносит с собой ответ на вопрос «где я нахожусь» — а это первое, что
человек теряет, вернувшись к вкладке через час.

**Текущий раздел отмечен тремя признаками сразу:** заливкой, цветом текста и
полосой у края. Одного цвета мало — его видят не все, а «где я» в меню человек
проверяет чаще, чем что-либо другое.

**Счётчик у раздела показывает работу, а не ноль.** «0 аварий» в меню занимает
место и не сообщает ничего, чего не сообщает отсутствие счётчика.

**Ссылка «К содержимому» — первая цель табуляции.** Без неё человек, работающий
с клавиатуры, проходит всё меню заново на каждой странице. `.dk-skip` не видно,
пока на неё не встал фокус.

### Нижняя панель на телефоне

На экране уже 768 px главные разделы стоят внизу, под большим пальцем, как в
приложении (`dk-tabbar`). Дашборд на телефоне открывают одной рукой, и до
кнопки разделов в верхнем углу палец не дотягивается.

```html
<nav class="dk-tabbar" aria-label="Главные разделы">
  <a class="dk-tabbar__item" href="dashboard.html" aria-current="page">
    <svg class="dk-i" aria-hidden="true"><use href="#ti-layout-grid"/></svg><span>Сводка</span></a>
  <a class="dk-tabbar__item" href="regions.html">
    <svg class="dk-i" aria-hidden="true"><use href="#ti-map"/></svg><span>Регионы</span></a>
</nav>
```

- **Разделов три–пять.** Шестой не помещается подписью, а значок без подписи
  — загадка. Полный список остаётся в меню за кнопкой разделов.
- **Текущий раздел отмечен тремя признаками**: вес подписи, цвет и крупный
  значок.
- **Панель лежит поверх содержимого.** Странице она сама даёт запас снизу на
  свою высоту, уведомления поднимаются над ней. Ей разрешены кромка,
  размытие фона и глубокая тень (`--elev-bar`), как всплывающему слою.
- **На широком экране панели нет**: там разделы в боковом меню, и вторая
  навигация была бы тем же списком дважды.

### Узкий экран: меню не выезжает

Разделы открываются **обычным всплывающим слоем** — тем же, что у фильтра: тень,
скругление, щелчок мимо закрывает, Escape возвращает фокус на кнопку.

Выезжающей панели здесь нет намеренно. Это отдельное движение, которое надо
заметить, понять и потом ещё закрыть; на узком экране она вдобавок накрывает
содержимое ровно там, куда человек смотрел. Одно поведение на весь интерфейс
лучше двух, даже если второе моднее.

Шапка на узком экране переносится в две строки: заголовок уходит под кнопки.
Инструменты нужны пальцу, заголовок — глазу, и глаз найдёт его в любой строке.

### Свёрнутое меню

`data-nav="folded"` — остаются значки, ширина падает до 64. Подписи при этом
**не показываются по наведению**: меню, которое читается только мышью,
недоступно с клавиатуры и с тачскрина. На узком экране свёрнутое состояние не
действует вовсе.

Состояние кит не запоминает: где его хранить — решает приложение. Библиотека не
знает ни про вход, ни про профиль пользователя.

## Модальное окно

Собрано на нативном `<dialog>`. Это выбор, обратный тому, что сделано с
фильтром: там нативный `<select>` не умел ничего из нужного и его пришлось
писать самим. Здесь наоборот — платформа даёт бесплатно ровно то, что своими
руками делается неделю и всё равно с ошибками: ловушку фокуса, недоступность
фона для скринридера, возврат фокуса на кнопку-открыватель. Кнопки внутри стоят
в `<form method="dialog">`, поэтому и закрытие работает без нашего кода.

```html
<button class="dk-btn" data-modal="#m-reset">Сбросить срез</button>

<dialog class="dk-modal" id="m-reset">
  <form method="dialog" class="dk-modal__form">
    <div class="dk-modal__head">
      <h2 class="dk-modal__title">Сбросить сохранённый срез?</h2>
      <button class="dk-iconbtn dk-iconbtn--sm" value="cancel" aria-label="Закрыть">…</button>
    </div>
    <div class="dk-modal__body">…что именно произойдёт…</div>
    <div class="dk-modal__foot">
      <button class="dk-btn" value="cancel" autofocus>Отмена</button>
      <button class="dk-btn dk-btn--primary" value="reset">Сбросить срез</button>
    </div>
  </form>
</dialog>
```

**Когда модалка.** Только для решения, которое нельзя отложить: подтвердить
необратимое, ответить на вопрос, без ответа на который дальше нельзя. Модалка
останавливает работу целиком — это её смысл и её цена. Всё, что можно сделать
не останавливая, делается панелью, страницей или всплывающим слоем.

**Заголовок модалки — единственное место в интерфейсе, где вопрос уместен.**
Решение принимает человек, и вопрос задан ему. Заголовок виджета вопросом быть
не может: виджет ничего не спрашивает.

**Фокус ставится на безопасную кнопку** — `autofocus` на «Отмене». Человек,
открывший окно случайно, закроет его пробелом, не потеряв ничего.

**Кнопка называет действие, а не согласие**, и с числом, если действие
необратимо: «Сбросить срез», а не «Продолжить». Подробнее — в разделе «Язык
интерфейса».

**Щелчок по подложке не закрывает.** Промах мимо окна — обычное дело, а потеря
введённого из-за промаха — нет. Закрывают Escape и крестик.

**Окно поверх окна не открывается.** Это интерфейс, который загнал человека в
угол и не даёт вернуться. Если решение требует второго решения, второе живёт
внутри первого окна. `dk-modal.js` закроет предыдущее и напишет об этом в
консоль.

Escape мы обрабатываем сами, хотя `<dialog>` обязан делать это без нас:
проверка показала, что полагаться на это можно не в любом окружении, а выход по
Escape — не украшение. Без него человек, открывший окно с клавиатуры, оказыва­ется
в ловушке.

## Календарь

Не выбор периода, а показ работы: что происходит и когда. Плановые отключения,
ремонты, проверки, аварии. Пример страницы — `calendar.html`.

```js
dkCalendar(document.getElementById('cal'), {
  view: 'month',                      // 'month' или 'week'
  month: '2026-09-01',
  events: [
    { date: '2026-09-14', name: 'Прорыв, Советский р-н', kind: 'crit' },
    { date: '2026-09-11', end: '2026-09-16', name: 'Ремонт теплотрассы', kind: 'high' },
    { date: '2026-09-23 03:20', end: '2026-09-23 09:40', name: 'Прорыв', kind: 'crit' }
  ],
  onSelect: function (date, events) { … },
  onEvent:  function (event) { … }
});
```

Три вида записи в одном списке. Без `end` — работа на один день. С `end` по
дате — длиннее дня. С часами в `date` и `end` — работа с временем, она попадёт
в недельную сетку.

Событие с часами, растянутое на несколько суток, показывается полосой, а не
в колонке часов: рисовать его кусками пришлось бы по дням, и куски считались бы
за отдельные работы.

Почему свой, а не готовый: календарь событий тянет за собой свою вёрстку, свои
цвета и свой словарь. Выбор периода мы взяли готовым именно потому, что там
цена своего решения — месяцы работы над мелочами (високосный февраль, летнее
время, склонение месяцев). Здесь таких ловушек нет: месяц раскладывается в
сетку двумя строками кода, а всё остальное — наши правила.

### Виды события

`kind` — это **смысл**, а не цвет: `crit` — авария, `high` — работа с
ограничением, `plan` — плановое, `calm` — завершено, `event` — событие без
оценки риска. Каждый вид берёт свой семантический токен.

Произвольного цвета у события нет и быть не может. Календарь, где цвета розданы
по кругу, врёт ровно так же, как график с произвольной палитрой: человек ищет
закономерность там, где её нет.

### Правила

**Сетка всегда в шесть строк.** В месяце помещается от четырёх с половиной до
шести недель. Если рисовать столько строк, сколько вышло, при перелистывании
страница прыгает, и человек каждый раз заново ищет глазами, где он был.

**Событие длиннее дня — одна полоса, а не повтор в каждом дне.** Повторённое
имя читается как несколько разных работ: «Ремонт теплотрассы» четыре дня подряд
выглядит как четыре ремонта. На переносе через воскресенье полоса обрывается
срезанным краем и продолжается на следующей строке — это край недели, а не край
работы.

**Больше трёх событий в дне — «ещё N».** Обрезать список молча значит скрыть от
человека часть его же работы.

**Сегодня отмечено заливкой под числом**, а не только цветом цифры.

**Дни соседних месяцев показываем приглушёнными.** Без них неделя рвётся, с
ними видно, что месяц начался не в понедельник.

**На узком экране события становятся точками.** Семь колонок по сорок пикселей
не вмещают ни одного названия; подробности человек открывает щелчком по дню.
Прятать их за наведением нельзя — на тачскрине наведения нет.

### Неделя с часами

`view: 'week'` — сутки по вертикали, дни по горизонтали. Высота полосы это
**длительность**: работа на два часа обязана выглядеть вдвое длиннее часовой,
иначе календарь врёт о нагрузке смены. Пересекающиеся работы делят ширину
колонки — иначе верхняя накрывает нижнюю, и человек не узнает, что в этот час
работ было две.

**Сутки показываются целиком.** Соблазн показать «рабочие часы» с 8 до 20 велик,
но авария в три часа ночи — это тоже работа, и спрятать её значит соврать о
сутках. Колонка прокручивается и открывается на первом событии недели, а не на
полуночи: ночь чаще всего пуста.

События без времени и длиннее суток идут полосой над сеткой часов: в часах им
места нет, а прятать их нельзя.

На узком экране недельная сетка прокручивается вбок. Ужать часы некуда — врать
о длительности нельзя, а семь колонок по сорок пикселей не вмещают ни одного
названия.

С клавиатуры работает как сетка: стрелки по дням, Home и End — края недели,
PageUp и PageDown — месяцы или недели, Enter — выбрать день. Переход стрелкой за
край сам перелистывает календарь.

## Движение

Движение в дашборде решает три задачи и никаких больше: показать, что
**появилось или исчезло**; связать **причину и следствие** — щёлкнул здесь,
открылось отсюда; **удержать взгляд на месте** при перестроении. Всё остальное
движение отнимает внимание у данных, ради которых человек пришёл.

| Длительность | Токен | Где |
|---|---|---|
| 120 мс | `--duration-fast` | состояние элемента: наведение, фокус, нажатие |
| 200 мс | `--duration-base` | появление слоя: меню, календарь, модальное окно |
| 260 мс | внутри обёртки графиков | перестроение графика при смене данных |

Дольше 300 мс в дашборде — это уже ожидание, а не подсказка.

### Кривая

| Что происходит | Кривая |
|---|---|
| появление и исчезновение | `--ease-out` |
| перемещение по экрану | `--ease-in-out` |
| наведение, смена цвета | обычный `ease` |

**Никогда `ease-in` в интерфейсе.** Он начинает медленно и крадёт ровно тот
момент, на который человек смотрит: `ease-out` за 200 мс кажется быстрее, чем
`ease-in` за те же 200 мс.

Встроенные в браузер кривые слишком вялые — у CSS `ease-out` почти прямая.
Поэтому в токенах лежат свои, взятые из готового набора, а не подобранные на
глаз: разницу между двумя кривыми видно только в сравнении сотни раз, и
подбирать её «по ощущению» бессмысленно.

```css
--ease-out:    cubic-bezier(.23, 1, .32, 1);
--ease-in-out: cubic-bezier(.77, 0, .175, 1);
```

Всплывающие слои появляются за 120 мс: сдвиг на четыре пикселя и прозрачность,
модальное окно — масштаб от 0.97. Не от нуля: из ничего в природе ничего не
появляется, и `scale(0)` выглядит как фокус, а не как открытие. Сделано на
`@starting-style` и `allow-discrete`, то есть без единой строки JS.

### Что можно

- **Смена цвета** при наведении и нажатии — она отвечает «эта штука нажимается».
- **Появление всплывающего слоя.** Слой должен показать, откуда он взялся,
  иначе выглядит как подмена страницы.
- **Перестроение графика** при смене периода или фильтра: видно, что картинка
  изменилась, а не что это другой график.
- **Скелет загрузки и неопределённый прогресс** — единственная бесконечная
  анимация, которая допустима, и только пока идёт работа.

### Чего нельзя

**Накручивать числа.** Счётчик, который «доезжает» от нуля до 1 284, нельзя
прочитать, пока он крутится, а в мониторинге число нужно сразу. Хуже того: он
изображает рост там, где данные просто загрузились.

**Показывать блоки по очереди.** Каскад при загрузке страницы выглядит дорого
ровно один раз, а потом каждый день отнимает секунду у того, кто открывает
дашборд двадцать раз в смену. Дашборд читают, а не смотрят.

**Анимировать обновление данных.** Если цифры обновляются раз в десять секунд,
любое движение превращает экран в мигалку. Новое значение просто заменяет
старое.

**Пульсировать, плавать, двигать фон.** Пульсация означает тревогу; если
пульсирует всё, тревога перестаёт читаться. Параллакс и плавающие элементы в
рабочем инструменте не значат ничего.

**Двигать то, на что человек целится.** Кнопка, которая отъезжает под курсором,
и строка, которая расширяется при наведении, приводят к промахам.

### Системная настройка сильнее нашей

`prefers-reduced-motion: reduce` обнуляет `--duration-fast` и `--duration-base`,
гасит пульсацию скелета и бесконечный прогресс, и то же самое делают графики и
карта — у ECharts анимация своя, и токены кита до неё не дотягиваются.

Это не вежливость: для части людей движение на экране вызывает тошноту и
головокружение. Настройку человек уже сделал в системе — переспрашивать его в
интерфейсе не нужно.

## Телефон и приложения

Дашборды кита открывают в браузере телефона, на планшете и внутри мобильных
приложений (WebView на Android, WKWebView на iOS). Правила ниже выведены из
замера, а не из макета. Первый прогон `tools/check-mobile.mjs` по 27 страницам
кита нашёл 1212 нарушений. Из них 2 дашборда были шире экрана, и три размера
под палец оказались привязаны к ширине, а не к касанию.

### Как проверяется

```bash
node tools/check-mobile.mjs            # все страницы, ~50 с
node tools/check-mobile.mjs dashboard.html
```

Скрипт открывает страницы в Chrome, который уже стоит на машине, без
установки пакетов. Размеров три:
- **Android 360×800** — самый узкий из массовых;
- **телефон боком 812×375** — с вырезом 47 px слева и справа и полосой «домой»
  21 px;
- **iPad 768×1024** — палец, но ширина планшетная.

Что меряется:
- страница не шире экрана, и виновник назван;
- касание в 21 px от центра каждой цели попадает в саму цель;
- шрифт полей не меньше 16 px;
- под вырез не уходят ни текст, ни значок, ни то, что нажимают;
- `theme-color` совпадает с фоном в обеих темах;
- ошибок в консоли нет.

Это проверка **ТЕЛЕФОН** в `check.py`. `--fast` пропускает браузерную часть и
честно печатает её знаком «?».

**Чего проверка не видит.** Эмулятор Chrome — не Safari и не WebView. Зум iOS
при фокусе в поле, настоящий вырез, строка состояния, системный крупный шрифт,
кнопка «назад» и загрузка файлов в приложении проверяются только на живом
телефоне. Список — в конце раздела. Меряется причина, которая к ним ведёт:
шрифт поля, `viewport-fit`, отступы.

### Касание

**Цель — 44 px, и решает указатель, а не ширина.** Все размеры управления
растут под `(pointer: coarse)` до 44 · 44 · 48. Раньше рост стоял на
`(max-width: 767px)`, и телефон боком (812 px) и iPad получали кнопки 28–32.
Мелкий размер и на узком экране оставался 36, то есть правило «44 независимо»
нарушали сами токены.

**Зона больше видимого — только когда соседей рядом нет.** Крестик сброса
20 px, стрелка сортировки, флажок получают невидимую зону 44 через `::after`.
Строки, которые нажимают целиком (рейтинг, «показать все», раскрывающийся
блок), растут видимо. Зона у строки легла бы на соседнюю строку, и касание
между ними уходило бы не туда. Проверка ловит и это: пишет, чья зона
перекрывает цель.

**Поле ловит касание по всей высоте.** Текст ввода растянут на высоту поля.
Раньше он был строкой в 22 px посреди поля в 44, и касание выше или ниже
строки попадало в обёртку. Мышью это не видно.

**Две цели не стоят ближе 44 между центрами.** Малые кнопки в строке таблицы
(«Открыть», «Ещё») на таче сами стали 44 и больше не делят зону.

### Раскладка дашборда на телефоне

**Страница никогда не шире экрана.** Всё широкое живёт в своей прокрутке:
- таблица — только прямо в `.dk-tablewrap`, это проверяется статически;
- вкладки и сегмент листаются вбок.

Без обёртки таблица либо распирает страницу, либо обрезается панелью с
`overflow: hidden`. Во втором случае колонки справа молча пропадают, и замер
ширины этого не видит.

**Абсолютно позиционированное внутри прокрутки — только если прокрутка его
держит.** Обёртка таблицы поэтому `position: relative`. Без этого подпись для
скринридера в шапке колонки действий вылезала из-под прокрутки. Дашборд
становился шириной 739 px при экране 360, аварии — 959.

**Шапка.** Период не обрезается: «Данные на 13:01» на узком экране уходит под
заголовок, иначе на период оставалось 166 px и чип показывал «Последни…».
Обрезанный период превращает дашборд в цифры неизвестно за что. На низком
экране (телефон боком) шапка не липнет: липкая занимала 38% высоты.

**График на телефоне — во всю ширину, то есть 310–340 px.** Восемь подписей
округов помещаются от 340 px («Подписи категорий»). Значит, на телефоне
названия (округа, дома, котельные) показывают полосами `bar-h`, где у каждой
подписи своя строка, а не столбцами. Число, ради которого график, не прячут
только в подсказку: подсказка на таче открывается касанием, и её не находят.

**Таблица.**
- Закреплённая колонка на телефоне не шире трети экрана. Было 234 px из 311,
  и на прокрутку оставалось 29.
- Колонка выбора — 48 px числом. Проценты у остальных колонок в сумме не
  больше 94, иначе раскладка сожмёт её до 19 px, и это видно и на десктопе.
- Действия строки видны всегда (наведения нет).

**Первый экран — главная карточка.** Сразу под строкой фильтров встаёт
`dk-hero`: одно число, «из скольких», метка смысла и полоса состава. Она
отвечает раньше любого графика. KPI-плитка, растянутая на всю ширину, сама
перестраивается: число слева, спарклайн справа. Растянутой полосой она
читалась пустой.

**Фильтры — строка пилюль, которая листается вбок**, а не стопка во всю
ширину (раздел «Фильтры»).

**Сегмент — не больше трёх вариантов на телефоне.** Больше — выпадающий список.
Не поместившийся сегмент листается вбок, как вкладки. Это страховка, а не
способ.

**Календарь.** В месяце на телефоне событие — отметка, а не цель: касание
проходит сквозь неё в день, и день открывает список. Раньше одно касание
делало две разные вещи в зависимости от пикселя. День шириной 39 px — законное
исключение: семь колонок на 360 шире не станут.

**Полоса доступности** на таче — строка 44. Полосы в 20 px через 8 — касание
наугад между двумя службами.

### iOS и Android

**Заголовок своей страницы** (`.dk-page`, кит владеет страницей):

```html
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
```

- `viewport-fit=cover` — иначе iPhone боком рисует по бокам чёрные поля. С
  этого момента страница сама отступает от выреза. Отступ стоит на `body`, и
  под него попадает всё сразу. Липкая шапка отступает сверху сама: при запуске
  с главного экрана под ней строка состояния. Уведомления отступают от полосы
  «домой».
- **`user-scalable=no` и `maximum-scale=1` — никогда.** Запрет масштабирования —
  это отказ в доступности. Проверка на них падает.
- **Строка состояния в цвет страницы.** `<meta name="theme-color">` ставит и
  меняет вместе с темой `dk-theme.js`, цвет берётся из `--bg`. Встроенный кит
  чужой `<head>` не трогает.
- **Текст не растёт сам.** `text-size-adjust: 100%` на `.dk-root`. Safari боком
  и Android с «ускорением шрифта» увеличивают мелкий текст каждый блок
  по-своему. `100%`, а не `none`: `none` в части браузеров отключает и
  масштабирование самим человеком.
- **Поля — 16 px под пальцем**, иначе iOS увеличит страницу при фокусе и обратно
  не уменьшит.
- **Высота — `dvh`.** Серой вспышки нет, задержки 300 мс нет, наведение закрыто
  от тача, прокрутка блока не утягивает страницу — всё прежнее, см. ниже.

Прежний список правил остаётся в силе:
- **Наведение закрыто от тача.** Все правила `:hover` — внутри
  `@media (hover: hover) and (pointer: fine)`; обратная связь пальцу — `:active`.
  Проверяет НАВЕДЕНИЕ.
- **Серой вспышки по касанию нет** (`-webkit-tap-highlight-color` на `.dk-root`).
- **Задержки в 300 мс нет** — `touch-action: manipulation` на всём нажимаемом.
  Долгое нажатие не выделяет текст кнопки.
- **Прокрутка внутри блока не утягивает страницу** (`overscroll-behavior: contain`).

Список сверен по открытому набору правил `mobile-native` Эмиля Ковальского
(MIT, автор Sonner и Vaul).

**Клавиатура.** Числовому полю — `inputmode="decimal"` (или `numeric` для
целых), телефону — `type="tel"`, почте — `type="email"`. Иначе на телефоне
открывается буквенная клавиатура, и цифру ищут на втором экране.

### Внутри приложения (WebView)

Страница кита в приложении — это своя страница (`.dk-page`), но хозяин вокруг —
приложение. Контракт:

**Меню и шапку кита в приложении не подключают.** Навигация, заголовок экрана
и «назад» — у приложения. Кит без каркаса — штатный режим (`chrome.css` и
`dk-chrome.js` необязательны). Период и фильтры остаются строкой над
содержимым.

**Тему задаёт приложение.**

```
https://…/dashboard.html?theme=dark
```

- `?theme=dark|light` главнее и сохранённого выбора, и системы. Иначе выбор,
  однажды сделанный в браузере этого телефона, перекрасил бы дашборд внутри
  приложения.
- В хранилище такая тема не пишется.
- Сменить на лету: `dkTheme.theme = 'light'` через `evaluateJavascript` /
  `evaluateJavaScript`.
- Свой переключатель темы на такой странице не ставят: два переключателя
  разойдутся.

**«Назад» сначала закрывает слой.**

```js
// Android, в onBackPressed / OnBackPressedCallback:
webView.evaluateJavascript("dkBack()", r -> { if ("false".equals(r)) goBackOrFinish(); });
```

`dkBack()` закрывает самый верхний открытый слой (список, период, разделы,
модальное окно) и отвечает `true`. Если закрывать нечего — `false`, и тогда
приложение уходит назад. Слои кита в историю не пишут намеренно: иначе «назад»
закрывало бы меню и в обычном браузере, где этого никто не просил. На iOS то
же для жеста назад, если приложение его включило. Проверено в Chrome:
- период, разделы и три модальных окна закрываются по одному;
- фокус возвращается на кнопку;
- на пустой странице ответ `false`.

Список внутри окна не проверен: на страницах кита такого сочетания нет.

**Вырез и системные панели — договорённость одна из двух:**
- приложение кладёт WebView в безопасную область, и тогда `env()` равны нулю,
  и странице делать нечего;
- WebView во весь экран, под системными панелями, и тогда отступает страница
  через `env(safe-area-inset-*)`.

WKWebView отдаёт `env()`. Поддержка в Android WebView зависит от версии и от
того, как приложение разложено, поэтому первый вариант надёжнее. Проверяется
только на устройстве.

**Файлы кита — через свою схему приложения, а не `file://`.** Кит офлайн-первый
и в приложение кладётся целиком. Но `fetch` контуров регионов
(`data/regions.topojson`) из `file://` WebView запрещает. На Android нужен
`WebViewAssetLoader`, на iOS — `WKURLSchemeHandler` или
`loadFileURL(_:allowingReadAccessTo:)` на всю папку кита.

**Выгрузка и внешние ссылки — дело приложения.** WebView по умолчанию не
скачивает файлы и не открывает новых окон. Кнопка «Выгрузить» в приложении
передаёт запрос хозяину, а не рассчитывает на загрузку браузера.

### С главного экрана (PWA)

Кит не поставляет продукту манифест, иконки и service worker: имя, значок и
то, что работает без сети, — решения продукта. Иконки продукт собирает
скриптом кита из своего знака (раздел ниже, «Иконки приложения, фавикон и
логотип»). У страниц самого кита свои иконки в `icons/`. Со стороны кита всё
готово:
- шапка и обёртка отступают от строки состояния;
- `theme-color` следует теме.

Образец для продукта:

```html
<link rel="manifest" href="manifest.webmanifest">
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">
<link rel="apple-touch-icon" href="icon-180.png">
```

```json
{ "name": "Мониторинг ЖКХ", "short_name": "ЖКХ", "start_url": "./dashboard.html",
  "display": "standalone", "background_color": "#18191E", "theme_color": "#18191E",
  "icons": [{ "src": "icon-512.png", "sizes": "512x512", "type": "image/png" }] }
```

`black-translucent` кладёт страницу под строку состояния, и отступ сверху
тогда делает шапка кита. `background_color` в манифесте статичен: это цвет
заставки при запуске. Бери цвет темы, в которой продукт открывается чаще;
после загрузки `theme-color` переключится сам.

### Иконки приложения, фавикон и логотип

У продукта одна форма — **знак**. Всё остальное выводится из неё скриптом,
а не рисуется шесть раз: нарисованные руками файлы расходятся с первой же
правкой знака, один обновят, пять останутся старыми.

```bash
node tools/build-app-icons.mjs --glyph bolt --accent blue --out icons
```

Скрипт кладёт в папку шесть файлов и печатает теги для `<head>`:

| файл | где | правило |
|---|---|---|
| `favicon.svg` | вкладка браузера | вектор, чёткий на любом экране |
| `icon-32.png` | вкладка, где SVG не понимают | 32×32 |
| `apple-touch-icon.png` | главный экран iPhone | 180×180, **без прозрачности** и без скругления: iOS скругляет сам, а прозрачное заливает чёрным |
| `icon-192.png`, `icon-512.png` | Android, установка с главного экрана | скругление 22%, знак 56% стороны |
| `icon-maskable-512.png` | Android со своей формой иконки | фон до краёв, знак 44% — внутри безопасного круга 80%, который Android не обрежет |

С `--manifest --name "…" --short "…"` скрипт соберёт и `manifest.webmanifest`
(образец — в разделе выше). Своя форма вместо значка из набора —
`--mark logo.svg`: квадратный SVG. Для маскируемой иконки и иконки iPhone он
уменьшается до безопасной зоны на фоне `--bg`.

**Правила знака:**
- **Одна простая фигура**, без текста и мелких деталей. Знак живёт в 16 px на
  вкладке. Проверяй его на листе всех размеров, а не на 512.
- **Цвет — акцент продукта**, фигура — светлая поверх него (`--brand` и
  `--brand-ink`). Цвета берутся из токенов: сменил акцент одной строкой —
  пересобрал иконки. **Смысловые цвета в знаке запрещены**: красный и зелёный
  в ките значат риск, и красный значок на главном экране читается тревогой.
- **Значок из набора кита** (`--glyph`) — это имя из `ICONS` в
  `tools/build-icons.py`. Нужен другой — впиши его туда и пересобери набор.

**Логотип** — знак плюс название, как в каркасе (`.dk-side__mark` и
`.dk-side__name`):
- название набирается Golos 600, своей гарнитуры у логотипа нет;
- между знаком и названием — шаг `--gap-inline`, вокруг логотипа пусто хотя
  бы на половину знака;
- знак не меньше 28 px, в свёрнутом меню остаётся только знак;
- на тёмной и светлой теме логотип одинаковый: знак залит акцентом и от фона
  не зависит.

Проверка ЗНАЧОК следит, что файлы, на которые ссылаются страницы, есть и
нужного размера, а иконка iPhone и маскируемая непрозрачны. Читается ли знак
в 16 px и помещается ли в безопасную зону — это глаз.

### Живой телефон: ручная проверка

Раз на выпуск, на одном iPhone (Safari) и одном Android (Chrome), плюс в
WebView приложения, если дашборд идёт туда:

1. Фокус в поле поиска и в поле формы — страница не увеличивается.
2. Телефон боком — ничего не под вырезом, фон доходит до края.
3. Строка состояния и адресная строка в цвет страницы в обеих темах.
   Переключение темы перекрашивает их сразу.
4. Системный крупный шрифт (Android: «Размер шрифта» на максимум; iOS: крупный
   текст) — плитки и таблица не разъезжаются, числа не переносятся по
   разрядам.
5. «Назад» при открытом периоде, списке, окне — закрывает слой, а не страницу.
6. Касание по полосе доступности, по дню календаря, по флажку в таблице —
   попадает с первого раза.
7. В приложении: тема из `?theme=`, контуры регионов загрузились, «Выгрузить»
   что-то делает.

Результат записывается в REVIEW.md, «Телефон и приложения», с моделью
телефона и версией системы. Непроверенное — тоже.

## Онбординг

**Онбординг встроен в интерфейс, а не наложен поверх.** Если функцию нельзя
объяснить на её месте, это дефект интерфейса, и тур со стрелками его не лечит —
он его прячет до следующего раза.

Что объясняет интерфейс сам:

- **пустое состояние первого входа** — оно отличается от пустого результата
  фильтра. «Под фильтры не попал ни один регион» и «здесь пока нет ни одной
  заявки, вот как добавить первую» — разные тексты и разные действия;
- **подсказка под полем** — требование, о котором человек узнаёт из ошибки, это
  требование, о котором ему не сказали вовремя;
- **подпись у виджета** (`dk-widget__hint`) — что именно показывает этот блок,
  если название не вмещает;
- **пример вместо пустоты.** Дашборд, открытый впервые, полезнее показать на
  демонстрационных данных с честной пометкой, чем пустым.

Если поверх всё-таки нужна подсказка:

- **не больше одной за сеанс** и только на действительно новое;
- **не при первом входе.** Человек ещё не понял, зачем он здесь, — сначала дайте
  ему увидеть свои данные;
- **с явным «понятно»**, которое запоминается. Подсказка, всплывающая снова,
  читается как поломка;
- **рядом с тем, что объясняет** — всплывающим слоем кита (`dk-pop`), а не
  модальным окном: модалка останавливает работу, а объяснение работу
  сопровождает.

Чего не делаем никогда: тура из пяти шагов при первом входе, затемнения всего
экрана ради одной подсказки, подсказок, которые нельзя закрыть, и «сделайте
ещё три шага, чтобы завершить настройку» на месте работающего интерфейса.

## Состояние страницы

Три разные вещи, которые часто путают: **вкладки** водят по разделам, **баннер**
отвечает за состояние всей страницы, **уведомление** подтверждает действие
человека.

### Вкладки

```html
<nav class="dk-tabs" aria-label="Разделы мониторинга">
  <a class="dk-tab" href="#" aria-current="page">Сводка</a>
  <a class="dk-tab" href="regions.html">Регионы</a>
  <a class="dk-tab" href="#">Аварии <span class="dk-tab__n">23</span></a>
</nav>
```

**Вкладка — не сегмент.** Сегмент переключает **вид** одних и тех же данных
(«карта / плитки», «месяц / неделя») и живёт внутри виджета. Вкладка водит по
**разным страницам** раздела: у неё свой адрес и своя загрузка. Перепутать
значит пообещать человеку не то — сегмент он ждёт мгновенным, вкладку нет.

Текущая отмечена подчёркиванием и цветом: одного цвета мало. На узком экране
вкладки прокручиваются вбок и не сворачиваются в «Ещё ▾» — спрятанный раздел
человек не находит.

### Баннер состояния

```html
<div class="dk-banner dk-banner--crit">
  <svg class="dk-i">…</svg>
  <div class="dk-banner__text">
    <div class="dk-banner__title">23 аварии требуют решения</div>
    <div class="dk-banner__sub">Рассылка жителям не отвечает три часа</div>
  </div>
  <div class="dk-banner__stats">
    <div class="dk-banner__stat"><b>9/11</b><span>служб</span></div>
  </div>
</div>
```

Баннер отвечает за состояние **всей страницы**. Ошибка внутри виджета остаётся
внутри виджета: она говорит про свой блок.

**Баннер о проблеме не закрывается.** Закрытая полоса про сбой — это сбой,
спрятанный руками человека, который через час о нём забудет. Полоса уходит
тогда, когда уходит причина. Закрывать можно только сообщение об успехе.

### Уведомление

```js
dkToast('Срез сброшен к настройкам по умолчанию', {
  action: { name: 'Отменить', onClick: function () { … } }
});
```

**Тост подтверждает действие человека, а не сообщает новости системы.** «Срез
сброшен» — да. «Авария в Новосибирске» — нет: уехавшее через пять секунд
сообщение о новой аварии это авария, которую никто не увидел. Состояние данных
живёт в самих данных и в баннере.

**То, что требует решения, не уезжает само.** Ошибку, которую надо исправить,
показывают на месте — у поля, в виджете, баннером.

**Время жизни считается по длине текста** (четыре секунды плюс сорок
миллисекунд на знак, не больше десяти), под курсором отсчёт стоит, а с кнопкой
«Отменить» тост живёт дольше: отмена, которую не успели нажать, — не отмена.
Одновременно видно не больше трёх.

## Полоса доступности

```js
dkUptime(el, {
  step: '30 минут', labels: ['24 ч назад', 'сейчас'],
  rows: [{ name: 'Приём заявок', data: ['up', 'up', 'down', …] }]
});
```

**Цена деления названа.** «Зелёно» без «каждое деление — 30 минут» не говорит,
сбой длился минуту или час.

**Легенда нужна до того, как понадобится.** Пока сбоев нет, полоса сплошь
зелёная, и кажется, что объяснять нечего. В момент первого сбоя человек впервые
увидит другой цвет — и будет гадать, что он значит, вместо того чтобы
действовать.

**«Нет данных» — не «работает».** Деление без замера серое и названо в легенде;
процент считается только по известным делениям. Закрасить непроверенное зелёным
значит пообещать работоспособность, которой никто не проверял.

## Строка с полосой

Имя, значение, полоса и мелкая строка подробностей — для списков вроде «кто
больше жжёт» и «кто чем занят».

```html
<div class="dk-bar" style="--accent:var(--crit)">
  <div class="dk-bar__head"><span class="dk-bar__name">Отопление</span><span class="dk-bar__v">520</span></div>
  <div class="dk-bar__track"><div class="dk-bar__fill" style="width:100%"></div></div>
  <div class="dk-bar__meta">41% обращений · 1 240 жителей · 18 бригад</div>
</div>
```

Полоса показывает долю **от максимума в этом же списке**, и это надо назвать в
заголовке блока — иначе читатель примет её за долю от целого. Значение цифрой
обязательно: полоса без числа читается как «примерно половина».

## Раскрывающийся блок

Нативный `<details>`: состояние, клавиатура и семантика достаются даром.

```html
<details class="dk-fold">
  <summary class="dk-fold__head">
    <span class="dk-fold__title">Вспомогательные серверы</span>
    <span class="dk-fold__sum">серверы 4/4 · туннели 3/3</span>
    <svg class="dk-i dk-i--sm">…</svg>
  </summary>
  <div class="dk-fold__body">…</div>
</details>
```

**Свёрнутым прячут подробности, а не то, без чего не понять.** Если человек
обязан развернуть блок, чтобы узнать состояние, — это не сворачивание, а
сокрытие. Поэтому в заголовке стоит итог.

## Регионы: карта и плитки

**Плитки увеличиваются кнопками + и −** (ступени 1, 1,5, 2, 3). На телефоне 89
плиток в 354 px — это клетки по 17 px: цвет видно, сокращение региона нет.
Увеличенная сетка листается внутри своей рамки, центр остаётся на месте. С
полутора сокращения возвращаются в плитки. Щипком не увеличивается: щипок на
странице увеличивает всю страницу, а с мышью его нет вовсе.

**Рамка карты — по пропорциям страны**, 1.9 : 1, не выше 420 px. Карта
заполняет её почти целиком. В ряду `dk-grid--stretch` высоту задаёт карта
(первая колонка), а список рядом листается внутри себя.

**Срез — `scope` или `setScope(ids)`.** Регионы вне фильтра (например, других
округов) приглушаются, а не красятся «нет данных»: серый значит «данных
нет», а у региона другого округа они есть. Шкала остаётся общей по стране,
поэтому один цвет значит одно и то же с фильтром и без. «Вне среза» есть в
легенде, в подсказке и в подписи для скринридера.

**Переключатель «карта / плитки» сам встаёт в шапку своего виджета.** Туда же,
где у всех виджетов действия. `controls` нужен, только чтобы поставить его
в другое место, `controls: false` — оставить отдельную строку над картой.

```js
dkMap(document.getElementById('map'), {
  topo: topojson, object: 'ru89',      // контуры
  tiles: tilesJson,                    // раскладка 19×11
  values: { moscow: 41, sakha: 78, … },
  unit: 'баллов риска',
  onSelect: function (id, value) { … }
});
```

**На карте площадь региона перебивает его значение.** Якутия занимает пятую
часть страны, Москва — точку; одинаковый цвет читается как «плохо на огромной
территории» и «почти ничего», хотя людей в Москве в двадцать раз больше. Карта
отвечает на вопрос «где» и отвечает хорошо. На вопрос «у кого хуже» она отвечает
неправильно — на него отвечают плитки, где у каждого субъекта равный вес.

Поэтому переключатель не настройка, а часть виджета, и убирать его нельзя.
Заодно он решает вторую задачу: **карта нарисована на canvas и с клавиатуры
недоступна**, а плитки — обычные кнопки, по которым ходят стрелками. Человек без
мыши получает те же данные, а не их пересказ.

**Цвет — лестница одного тона** (`--seq-1…5`), светлое мало, тёмное много.
Радуга заставляет вспоминать легенду на каждом регионе.

**Пороги названы числами.** «Мало / средне / много» — это не легенда, а
обещание, что читатель сам угадает, сколько это.

**«Нет данных» — отдельная категория, а не ноль.** Такой регион серый
(`--nodata`) и назван в легенде: ноль это ответ, отсутствие — нет.

### Почему проекция и почему свой разбор TopoJSON

Проекция — равновеликая коническая (Альберс, стандартные параллели 52° и 64°).
Взята не ради красоты: на карте, где цветом кодируют величину, площадь читается
как вес, и проекция, раздувающая север, врёт о весе Ямала и Чукотки.

TopoJSON разбирается своей функцией, а не библиотекой: нужна ровно одна
операция, а `topojson-client` — ещё один чужой файл в офлайн-репозитории,
который потом никто не обновляет. Формат простой: дуги записаны приращениями и
квантованы, минус у номера дуги означает «эту же дугу задом наперёд».

**Данные подаются объектами, а не читаются китом самостоятельно.** На `file://`
браузер запрещает `fetch`, и виджет, который сам лезет за файлом, на двойной
клик просто не открылся бы. Страницы с картой нужно открывать по http — это
ограничение браузера, не кита, и в примере на этот случай стоит объяснение
вместо пустого прямоугольника.

## Формы

Дашборд не только показывает, но и принимает: заявку, работу, комментарий.
Форма здесь почти всегда короткая, и правила у неё жёстче обычных — человек
заполняет её между двумя срочными делами.

```html
<form class="dk-form">
  <div class="dk-form__alarm" hidden></div>

  <div class="dk-ff dk-ff--wide">
    <label class="dk-label" for="name">Что за работа</label>
    <div class="dk-field"><input id="name" required minlength="5"
         placeholder="Замена задвижки на вводе"></div>
    <div class="dk-hint">Так её увидят диспетчеры смены в календаре</div>
  </div>

  <div class="dk-form__foot">
    <button type="button" class="dk-btn">Отмена</button>
    <button type="submit" class="dk-btn dk-btn--primary">Добавить работу</button>
  </div>
</form>
```

```js
dkForm(form, {
  check: function (el) { … },        // своя проверка сверх браузерной
  onSubmit: function (data, form) { … }
});
```

**Подпись стоит над полем, а не внутри.** Плейсхолдер исчезает при вводе: стоит
отвлечься на звонок — и человек смотрит на заполненное поле, не понимая, что в
нём. Внутри поля живёт **пример** значения, а не его название.

**Подсказка объясняет требование заранее.** Требование, о котором человек
узнаёт из ошибки, — это требование, о котором ему не сказали вовремя.

**Отмечаем то, чего меньше.** Если обязательны почти все поля, пометка у
каждого превращается в шум — тогда помечают необязательные (`dk-label__opt`).
Если обязательных мало — помечают их (`dk-label__req`). Оба способа сразу — это
витрина, а не форма.

### Проверка

Правила берутся у браузера: `required`, `minlength`, `min`, `max`, `pattern`,
`type="email"` он проверяет сам и одинаково во всех полях. Своего у нас две
вещи: **когда** показывать ошибку и **какими словами**. Пузыри браузера
выключены — они исчезают сами и не читаются с клавиатуры.

**Ошибка говорит, что сделать, а не что не так.** «Не короче 5 знаков — сейчас
3» вместо «Неверное значение»: человек уже знает, что ошибся, — ему нужно знать,
как исправить.

**Не проверяем на каждом нажатии.** Первая проверка — когда человек ушёл из поля
или отправил форму. Иначе он видит «слишком короткое значение», не дописав
второй буквы, и это выглядит как придирка. Но поле, **уже** помеченное ошибкой,
проверяется на каждом нажатии: тогда ошибка исчезает сразу, как только
исправлена.

**Ошибка живёт под полем**, со значком и `role="alert"`, а не в углу экрана:
сообщение вдали от поля заставляет искать, к чему оно относится.

**Фокус уходит на первое неверное поле.** Форма, которая молча не отправилась, —
это форма, которую человек перечитывает сверху вниз, ища, что не так. Над формой
при этом появляется строка «Полей заполнено неверно: 3».

**Связь двух полей — это `check`.** Браузер не знает, что окончание не может
быть раньше начала: это знает предметная область, и такие правила пишутся руками.

**Форма в модальном окне не использует `method="dialog"`.** Он закрывает окно до
проверки — то есть теряет введённое вместе с ошибками. Закрытие вешается на
кнопки вручную, проверка важнее экономии на двух строках.

## Таблица карточками на телефоне

`dk-table--cards` — на экране уже 768 px строка таблицы становится карточкой.
Первая колонка — заголовок карточки, остальные — пары «подпись — значение».
Шапка превращается в строку пилюль сортировки: сортировать можно и на
телефоне. Без модификатора большая таблица на телефоне показывала сразу одну
колонку, а ради чего её открывают, пряталось за прокруткой вбок.

- **Подписи ставит `dkTable`** (атрибут `data-label` по заголовку колонки).
  Строки, которые страница дорисует потом, получают подписи сами. Без
  `dkTable` карточки будут без подписей.
- **На широком экране это обычная таблица.**
- **Когда брать:** таблица шире экрана телефона, больше трёх колонок. Узкую
  таблицу из двух-трёх колонок оставь таблицей.

## Типы ячеек таблицы

Таблица из одного текста — это список, а не таблица. Рабочая строка несёт пять
разных вещей, и у каждой своя форма.

| Ячейка | Класс | Для чего |
|---|---|---|
| выбор строки | `dk-td-pick` | флажок; в шапке — «выбрать все» |
| главная | `dk-td-main` | значок, название и подпись «где и когда» |
| состояние | `dk-status` | значок плюс слово, а не только цвет |
| доля | `dk-td-bar` | полоса с числом рядом |
| число | `dk-td-num` | вправо, табличными цифрами |
| действия | `dk-td-act` | кнопки в конце строки |

```html
<td data-sort="Прорыв теплотрассы">
  <div class="dk-td-main" style="--accent:var(--crit)">
    <span class="dk-td-main__icon">…</span>
    <span class="dk-td-main__text">
      <span class="dk-td-main__name">Прорыв теплотрассы</span>
      <span class="dk-td-main__sub">Новосибирская область · № 4821</span>
    </span>
  </div>
</td>
```

```js
dkTable(document.getElementById('table'), {
  onSelect: function (ids) { … },     // выбранные data-id строк
  onSort:   function (v) { … }        // передан — сортируем не мы, а приложение
});
```

**Действия не прячутся под наведение.** Это самый распространённый приём в
админках и самая дорогая ошибка: на тачскрине наведения нет вовсе, а с
клавиатуры спрятанное действие не найти. Кнопки стоят всегда, приглушённо, и
проявляются на строке под курсором — место они занимают в любом случае, поэтому
строка не дёргается.

**Выбранное видно числом, а не только заливкой.** «Выбрано 12» — это то, что
человек проверяет перед тем, как нажать «Удалить». Заливка строк отвечает
«какие», число отвечает «сколько», и второе важнее: строк может быть больше,
чем помещается на экране.

**«Выбрать все» значит «все на этой странице».** Обещать выбор всех 214 записей,
отметив 20 видимых, — ложь, за которую расплатится тот, кто следом нажмёт
«Удалить». Промежуточное состояние флажка показывает, что выбрана часть.

**Полоса в ячейке всегда с числом.** Полоса без числа читается как «примерно
половина» и не годится там, где решают по цифре.

**У шапки таблицы нет скруглений.** Скруглённый угол отделяет блок от фона, а
шапка не блок: она верхняя строка таблицы, и закруглять её значит обещать конец
там, где начинаются данные.

**Сортировка называет направление.** Стрелка показывает не «здесь можно
сортировать», а куда именно отсортировано; скринридеру то же самое говорит
`aria-sort`. Сортируем по значению из `data-sort`, а не по тому, что написано:
«1 240 чел.» и «14:20» — это текст, а порядок у них числовой и временной.

## Постраничная навигация

```js
dkPager(document.getElementById('pager'), {
  total: 214, size: 20, page: 1,
  sizes: [10, 20, 50],                      // не передавать — размер не меняется
  noun: ['заявка', 'заявки', 'заявок'],
  onChange: function (v) { … }              // { page, size, from, to }
});
```

**Сначала объём, потом кнопки.** «Показано 21–40 из 89» отвечает сразу на три
вопроса: где я, сколько вижу и сколько есть. Полоса из одних стрелок оставляет
человека листать вслепую — он не знает, десять там записей или десять тысяч.

**Крайние кнопки отключаются, а не исчезают.** Исчезнувшая кнопка сдвигает
соседнюю под курсор, и следующий щелчок попадает не туда, куда целились. Это
самая обидная ошибка в списках: хотел «вперёд», получил «в конец».

**Текущая страница отмечена заливкой**, а не только цветом цифры, и несёт
`aria-current`.

**Страницы не перечисляются все.** Больше семи номеров подряд человек не читает,
а пересчитывает: показываем окно вокруг текущей и края, между ними многоточие.
Ширина полосы при этом не скачет от страницы к странице.

**Смена размера страницы держит первую видимую запись на месте.** Иначе человек,
переключивший «20» на «50», проваливается в другое место списка и теряет то, что
читал.

На узком экране номера скрываются: пальцем в цифру шириной 28 пикселей не
попасть. Остаются стрелки и «3 из 12».

## Шрифт и числа

**Гарнитура одна — Golos Text**, и она лежит в репозитории: `vendor/fonts/`,
четыре начертания с латиницей и кириллицей, 235 КБ. Крупные числа KPI до
29.09.2026 набирались широкой Unbounded. Теперь и они Golos 600, как главное
число экрана (DECISIONS.md, п. 8). Файлы Unbounded удалены из
`vendor/fonts/`.

Раньше шрифт тянулся с Google. Кит заявлен офлайновым, ECharts и календарь
положены в `vendor/` именно ради этого — а без сети подставлялась запасная
гарнитура, и вместе с ней пропадали табличные цифры. То есть колонка чисел
начинала дрожать ровно тогда, когда отвалилась связь. Страницы в интернет за
шрифтом больше не ходят.

### Табличные цифры работают наполовину — и это надо знать

У Golos Text нет полноценных табличных цифр. Свойство `tabular-nums`
применяется, но выравнивает только единицу: остальные цифры остаются четырёх
разных ширин. Измерено — разброс 1.6 px при кегле 40, против нуля у гарнитур с
настоящими табличными.

На кегле 14 это 0.56 px на знак. В колонке коротких чисел незаметно; на длинных
числах разряды слегка расходятся, и счётчик, обновляющийся раз в десять секунд,
чуть подрагивает.

Вторую гарнитуру только под цифры мы пробовали и **отказались**: ради
полупиксельного выравнивания интерфейс получал второй голос, а единство
важнее. Цена принята осознанно, и написано это здесь, чтобы обещание кита
совпадало с тем, что он делает. Раньше README обещал, что «разряды обязаны
стоять друг под другом» — это было неправдой, и неправдой молчаливой.

**Крупные числа набираются пропорциональными цифрами**, а не табличными. У
табличной единицы широкие боковые поля, чтобы встать в колонку, и в числе «17»
появляется зазор, из-за которого оно читается как два числа. Табличные цифры
придуманы для колонок — там они и стоят.

**Моноширинный объявлен системным.** Раньше `--face-mono` был назван IBM Plex
Mono, которого в репозитории нет: он никогда не загружался и молча подменялся
системным, то есть код выглядел по-разному на разных машинах. Теперь в токене
написано то, что произойдёт на самом деле.

## Клавиатура и скринридер

Кит проверяет цвет машиной, а доступность до сих пор держалась на внимательности.
Аудит показал, где она не выдержала, — все находки ниже были живыми дефектами,
а не гипотезами.

**Перерисовка не должна ронять фокус.** Пагинация переписывала себя целиком, и
человек, листающий журнал заявок с клавиатуры, после каждого нажатия оказывался
в начале документа и заново пробегал табом шапку, меню и фильтры. Теперь перед
перерисовкой запоминается, на какой кнопке стоял фокус — по смыслу, а не по
узлу, — и возвращается на неё же. Если кнопка стала недоступной (край списка),
фокус переходит на соседнюю, а не проваливается.

**Сетка — это один вход и стрелки.** У карты 89 плиток; каждая была
самостоятельной целью табуляции, то есть пройти виджет насквозь стоило 89
нажатий. Теперь в табуляции ровно одна плитка, между ними ходят стрелками, и
tabindex переезжает вместе с фокусом — выйти из сетки человек должен туда же,
откуда вошёл. Так же устроен календарь.

**То, что показывает подсказка, обязано быть и без подсказки.** Значение региона
жило в `title`: плитки объявлены ответом на вопрос «у кого хуже», а ответ был
доступен только мыши. Теперь число стоит в самой плитке. Полоса доступности
рисуется ради вопроса «когда именно был сбой» — деления не брали фокус и не
имели текста; теперь полоса берёт фокус целиком, стрелки ходят по делениям, а
выбранное называется словами в строке под ней.

**Заголовок виджета — заголовок, а не `div`.** На собранном дашборде их было
двенадцать, и все — обычные блоки: скринридер читал плотный экран сплошным
потоком чисел, перепрыгнуть между блоками было нечем.

**Сегмент объявляется группой, а не вкладками.** `role="tablist"` обещает смену
страницы и новую загрузку, а сегмент перерисовывает тот же виджет. Это та же
граница, что описана в разделе «Состояние страницы», только для скринридера.

**Загрузка объявляет себя.** Скелет был только фоном с пульсацией — человек со
скринридером не отличал «данные едут» от «данных нет». На виджет ставится
`aria-busy`, внутрь — одна невидимая строка текста.

**Область нажатия на пальце — 44 пикселя, даже если элемент меньше.** Крестик
сброса периода в 20 пикселей стоит вплотную к триггеру фильтра: промах снимал
период, то есть молча менял срез всего дашборда. Растёт зона, а не видимый
размер, и растёт псевдоэлементом — `padding` сдвинул бы соседей.

**Тема помнится между страницами.** Она жила только в витрине: диспетчер
переключал тему, уходил по вкладке в «Календарь» и снова получал тёмную. За
смену это повторяется десятки раз. Если человек ничего не выбирал, берётся
системная настройка, а не приколачивается тёмная.

## Цвет проверяется машиной

Три проверки, которых раньше не было, и все три нашли живые дефекты.

**Ступень между поверхностями.** Границ у кита нет: блок отделяется от соседа
только тем, что он светлее. Пока это не проверялось, в светлой теме вложенная
поверхность отличалась от виджета на 1.05:1 — то есть не отличалась вовсе, — а
третья совпадала с фоном страницы цвет в цвет. На этих токенах висят курсор
клавиатуры в меню, подсветка строки таблицы и заливка всех полей: в светлой
теме их просто не было видно. Лестница пересчитана, поверхности углублены,
вторичный текст опущен на ступень вслед за ними.

**Акцент против смысла.** Кит морозил хэшем палитру серий и гонял её на
дальтонизм — а пару «бренд против состояния» не проверял ни разу, хотя цена
ошибки выше: серия отвечает на вопрос «кто это», смысл — «насколько всё плохо».
Проверка нашла, что синий акцент, стоящий по умолчанию, при красно-зелёной
слепоте сливался со слоем событий: ΔE 5.5 при пороге 15. Синяя кнопка и метка
БПЛА читались одним цветом.

Порог общий с палитрой серий — 15, и проверяется он в норме, при протанопии,
дейтеранопии и тританопии. Для тританопии порог ниже (10): она встречается у
сотых долей процента, и требовать от пятицветной палитры полного расхождения
ещё и по ней — значит не собрать палитру вовсе.

**Подпись и силуэт кнопки.** Обводок нет, поэтому форму залитой кнопки держит
только её заливка против поверхности. Проверяются оба порога сразу: подпись на
кнопке 4.5:1, силуэт кнопки 3:1. Три акцента из пяти проваливали первое, два —
второе.

Сдвиги посчитаны, а не подобраны на глаз: синий и фиолетовый ушли на ΔE 1–2,
это за порогом различимости; индиго и серо-синий стали чуть светлее. У
бирюзового цвет не менялся вовсе — ему сменили цвет подписи на тёмный, и он
проходит порог с запасом (5.1:1 против 3.3:1 с белой).

**Бирюзовый и серый убраны из акцентов.** Это то же правило, что уже стояло в
примитивах про красный, жёлтый и зелёный: акцент не занимает тон, занятый
смыслом. Бирюзовый при красно-зелёной слепоте становится серым и сливался с
«нет данных» (ΔE 2.5 при пороге 15), при тританопии подходил к зелёному
«низкий риск». Серый — это и есть «нет данных». Значения, которое остаётся
бирюзовым и проходит оба порога, не существует: перебран тон ±25°, вся
светлота и насыщенность. Осталось три акцента — синий, фиолетовый, индиго.

**Шкала карты разведена по темам.** Раньше обе брали одну лестницу: светлое
мало, тёмное много. На тёмной доске самый тёмный конец — «много баллов риска» —
давал 1.45:1 к виджету, и проблемные регионы исчезали. Именно те, ради которых
карту и открывают. Направление смысла одно и то же, меняется светлота.

**`palette: 'status'` у графиков.** Категории «высокий / средний / низкий / нет
данных» — это состояние, а не принадлежность, и красить их палитрой серий
значит врать: безопасное горит тёплым, опасное холодным, а «нет данных»
получает цвет серии и притворяется значением. В витрине это было в двух
графиках из трёх.

**`--watch` удалён.** Он отличался от `--high` на ΔE 12.5 при собственном
пороге 15, то есть был вторым названием того же жёлтого, и использовался ровно
в одном месте — в свотче витрины. Два имени для одного цвета — это приглашение
использовать их как разные смыслы.

**Слой событий сдвинут** с `#7C3AED` на `#A881CF`: тот же фиолетовый тон, но
светлее и мягче. Причина не в красоте — прежнее значение сливалось с синим
акцентом при дальтонизме. Новое расходится со всеми пятью акцентами и всеми
смысловыми тонами с запасом в полтора-три раза.

## Скругления

Три правила, из которых следует вся лестница.

**1. Радиус растёт вместе с блоком.** Мелкая метка 4, кнопка 10, виджет 16.
Один радиус на всё выглядит либо как набор коробок, либо как россыпь леденцов:
у крупного блока мелкое скругление теряется, у мелкого крупное съедает
содержимое.

**2. Вложенный радиус = внешний минус отступ.** Сегмент внутри дорожки: дорожка
10, отступ 4, сегмент 6. Если этого не сделать, дуги не будут параллельны —
зазор между внутренним и внешним углом окажется шире, чем по прямой. Глаз
ловит это сразу, хотя человек обычно не может объяснить, что именно не так.

**3. Радиус не больше трети высоты.** Дальше прямоугольник превращается в
таблетку, а таблетка означает другое: тег, статус, фильтр-метку, но не кнопку.
Настоящие таблетки берут `--radius-full` и делают это осознанно.

| Токен | Значение | Где |
|---|---|---|
| `--radius-xs` | 4 | бейдж, свотч, скелет загрузки |
| `--radius-sm` | 6 | сегмент внутри дорожки, строка списка |
| `--radius-md` | 10 | кнопка, поле, чип, иконочная кнопка |
| `--radius-lg` | 12 | блок внутри виджета: сводка, KPI-плитка |
| `--radius-xl` | 16 | виджет, панель, всплывающее меню |
| `--radius-full` | 999 | точка, аватар, круглая метка |

## Размеры элементов управления

Три: **S · 28**, **M · 32**, **L · 40**. Под пальцем — **44 · 44 · 48**: на
таче различие S и M пропадает, потому что мельче 44 цель быть не может
(«Телефон и приложения»). По умолчанию M — он стоит в девяти
случаях из десяти. S для плотных мест: панель фильтров, действие внутри строки
таблицы. L для одиночного главного действия на странице.

```html
<button class="dk-btn dk-btn--primary dk-btn--lg">Построить отчёт</button>
<button class="dk-btn dk-btn--sm">Сбросить</button>
<button class="dk-iconbtn dk-iconbtn--sm" aria-label="Настройки">…</button>
```

Те же три размера у иконочной кнопки, сегментов и **фильтров-чипов**
(`dk-lg--sm`, `dk-lg--lg`) — фильтр стоит с кнопками в одном ряду, и разнобой
по высоте виден сразу. Поле ввода по умолчанию L: в него пишут и в него
целятся, мелкое неудобно; `dk-field--md` для плотной панели фильтров.

Больше трёх размеров не заводим: каждый лишний — это ещё одно решение, которое
кто-то примет неправильно.

**У иконочной кнопки обязательны две подписи сразу:** `aria-label` для
скринридера и `title` для подсказки при наведении. Значок без подписи понятен
тому, кто его нарисовал; остальные гадают. Кнопка при этом квадратная и берёт
высоту из той же шкалы — иконка в «плавающей» форме перестаёт читаться как
кнопка.

## Фильтры

Три вида на одной основе: одиночный выбор, множественный и с поиском. Вид
выбирается **по длине списка**, а не по вкусу: до восьми значений — простой
список, до двадцати — с поиском, дальше поиск обязателен.

```js
dkSelect(document.getElementById('f-okrug'), {
  label: 'Округ',
  options: [{ value: 'cfo', name: 'Центральный', count: 18 }, …],
  onChange: function (v) { … }
});
```

`mode: 'multi'` — множественный выбор.

**Фильтр — пилюля по своему содержимому, строка фильтров — прямо на странице**,
над содержимым, а не внутри панели:

```html
<div class="dk-toolbar">
  <div class="dk-toolbar__group">
    <div id="period"></div>
    <div id="f-okrug"></div>
  </div>
</div>
```

На доске страницы у пилюли тонкая кромка и мягкая тень. Без них на тёмной
доске пилюля читалась дыркой, а не кнопкой. Это единственная рамка в ките
(DECISIONS.md, п. 8). Внутри панели, виджета или окна та же пилюля становится
плоской: вложенная заливка без кромки и тени.

**На телефоне строка фильтров листается вбок.** Раньше каждый фильтр
растягивался на всю ширину и вставал в стопку: «Округ ⌄» слева в полосе на
433 px читался пустой полосой, три фильтра съедали пол-экрана. Теперь пилюли
по содержимому, а не поместившиеся уходят за край и видны краешком — это
подсказка «листай». Меню из такой строки открывается поверх страницы, под
своей кнопкой и не шире экрана (`dkAnchor` в `dk-util.js`): внутри прокрутки
оно было бы обрезано.

### Правила поведения

Они важнее внешнего вида: фильтр — то место, где человек чаще всего
обманывается насчёт того, какие данные перед ним.

**1. Выбранное видно, не открывая меню.** Фильтр, который после выбора
продолжает показывать «Все округа», — источник самых дорогих ошибок в
дашбордах: человек смотрит на срез и уверен, что видит всё. Поэтому подпись
меняется на значение, фильтр получает серый оттенок выбранного (не акцент:
управление тише данных), а под панелью идёт строка применённого и счётчик
«23 из 89».

**2. Одиночный выбор применяется сразу и закрывает меню, множественный —
остаётся открытым.** Человек ещё не закончил. Смешивать эти два поведения
нельзя: пользователь перестаёт понимать, когда фильтр сработал.

**3. Рядом со значением стоит число записей.** Без него выбор делается вслепую
и приводит в пустой результат. Значение с нулём не прячем, а показываем
приглушённым: «здесь пусто» — это тоже ответ.

**4. Сброс живёт на самом фильтре, а не внутри меню.** Снять фильтр должно быть
так же легко, как поставить.

**5. Выбор отмечен не только цветом** — галочкой или квадратиком. Цвет видят не все.

Всё работает с клавиатуры: стрелки, Home, End, Enter, Escape с возвратом фокуса
на фильтр.

## Лента карточек

«Резко выросли за день», «В фокусе дня» — несколько объектов, у каждого своя
история: было → стало, причина, где (`dk-car`). Карточки листаются вбок и
прилипают левым краем. На телефоне видна одна целиком и краешек следующей:
это подсказка, что их несколько.

- **Разметку пишет страница, `dkCar(el)` её оживляет**: счётчик «1 из 5»,
  точки под лентой, стрелки на экране с мышью. Колесом вбок листает не каждая
  мышь.
- **Позиция — словами.** Точки при счётчике — подсказка, скринридеру они
  скрыты.
- **Все карточки помещаются — счётчика, точек и стрелок нет.** «3 из 3» при
  трёх видимых было бы неправдой.
- **Оттенок у каждой карточки свой**, по смыслу (`--accent`): это разные
  объекты с разным риском.
- **Карточек 3–7.** Больше — рейтинг или таблица: до последней не долистают.

## Поиск

Главный поиск экрана — «Регион или округ» — и дата, на которую данные
(`dk-search`). На телефоне это первое, что видит человек. Поэтому поиск
крупнее поля формы (56 px) и лежит на доске пилюлей с кромкой и тенью. Внутри
панели или виджета он плоский.

```html
<div class="dk-search">
  <svg class="dk-i dk-search__icon" aria-hidden="true"><use href="#ti-search"/></svg>
  <input class="dk-search__input" type="search" placeholder="Регион или округ"
         aria-label="Найти регион или округ" enterkeyhint="search" autocomplete="off">
  <button type="button" class="dk-search__clear" aria-label="Очистить поиск">
    <svg class="dk-i" aria-hidden="true"><use href="#ti-x"/></svg></button>
  <span class="dk-search__at" title="Данные на 29 сентября">29.09</span>
</div>
```

- **Своего скрипта нет.** Крестик очищает поле без подключения: это делает
  `dk-util.js`, который стоит на каждой странице. После очистки поле
  получает событие `input`, так что страница узнаёт об очистке тем же путём,
  что и о вводе.
- **Пока ищут, дата уступает место крестику**: искомое важнее. Дата
  возвращается, когда поле опустеет.
- **Кегль поля 16.** При меньшем iOS увеличивает страницу при фокусе.
- **Подпись — `aria-label`.** Подсказка исчезает при вводе и подписью не
  считается.

## Выбор периода

Тот же фильтр, только значение — время. Стоит первым в панели: период
ограничивает всё остальное, и человек читает его первым.

```js
dkPeriod(document.getElementById('f-period'), {
  label: 'Период',
  value: { preset: 30 },                  // либо { from: Date, to: Date }
  onChange: function (v) { … }            // { from, to, preset }
});
```

Три пресета — 7, 30 и 365 дней — и произвольный диапазон в календаре.
`from` приходит началом суток, `to` — концом: период «по 5 октября» обязан
включать весь день целиком, иначе записи, сделанные днём, молча выпадут из
выборки, и это заметят через недели.

Внутри лежит Air Datepicker (MIT, 66 КБ на два файла, русский язык из коробки).
Свой календарь не пишем: переходы через границу месяца и года, високосный
февраль, склонение месяцев, стрелки внутри сетки дней и объявление диапазона
скринридеру — это неделя работы и годы багов доступности.

Из двух готовых библиотек выбрана эта, потому что она отдаёт наружу семьдесят
CSS-переменных и потому перекрашивается целиком нашими токенами. У flatpickr
таких переменных нет вовсе — цвета вшиты в код, и его пришлось бы перебивать
поверх, а это ровно то, что кит запрещает. Вся внешность календаря собрана в
`components.css`, в чужой файл мы не лезем и при обновлении версии ничего не
теряем.

### Правила поведения

Первые пять — те же, что у фильтров, и по той же причине: период врёт дороже
всех. Человек, который смотрит на график за неделю, думая, что видит год,
сделает неверный вывод и не заметит этого. К ним добавляются три своих.

**6. Кнопки «Применить» нет.** Пресет применяется по щелчку, диапазон — когда
названа вторая дата. Лишний шаг — это шаг, на котором забывают нажать и уходят
с несохранённым выбором.

**7. Половина диапазона не применяется.** Если календарь закрыли, назвав одну
дату, возвращается прежний период: иначе «с 5 октября по 5 октября» молча
подменит собой год данных.

**8. Будущего в дашборде нет.** Дни после сегодняшнего закрыты — данных за них
не существует, и выбрать их значит получить пустой график и не понять, почему.
Открыть будущее можно параметром `maxDate`, но по умолчанию оно закрыто.

Стрелки ходят по пресетам, внутри календаря они принадлежат ему — там ими
двигают по дням. Escape закрывает и возвращает фокус на фильтр.

## Атомы

Мелкие детали, из которых собраны таблицы и карточки.

### Бейдж, статус и тег — разное

Их путают чаще всего.

- **Бейдж** отвечает на «сколько» или «что за штука»: число либо короткая метка.
- **Статус** отвечает на «как дела» и обязан иметь **и значок, и подпись**.
  Только цветом состояние не показывают никогда: цвет видят не все, а в
  чёрно-белой печати его нет вовсе.
- **Тег** — снимаемая категория, это `dk-fchip` из строки фильтров.

### Флажок, радио и тумблер обещают разное поведение

| Элемент | Когда | Поведение |
|---|---|---|
| Флажок | независимое «да/нет», можно несколько | применяется по кнопке |
| Радио | взаимоисключающий выбор, 2–5 вариантов, все видны | применяется по кнопке |
| Тумблер | режим: «показывать события», «тёмная тема» | **срабатывает сразу** |

Больше пяти вариантов — это выпадающий список, а не радио. Снять выбор в радио
нельзя: если «ничего» допустимо, нужен такой вариант явно.

**Тумблер в форме, которую надо сохранять, — обман:** человек переключил, ушёл,
а ничего не сохранилось. Подпись всегда кликабельна: попасть в квадратик
18 пикселей тяжело, а в строку с текстом — легко.

### Прогресс

Полоса **без числа — украшение**: «примерно две трети» нельзя ни записать, ни
обсудить. Число рядом обязательно. Неопределённый прогресс (не знаем, сколько
осталось) числа не имеет и показывается бегущей полосой — врать процентом нельзя.

### Аватарки

Картинка может не загрузиться, поэтому всегда есть запасной вариант из инициалов.
Группа перекрывается с кольцом цветом поверхности и заканчивается «+N». Аватарка
без подписи ничего не сообщает скринридеру — имя идёт в `aria-label` или рядом
текстом.

### Полосы прокрутки

**Полосу прокрутки не прячут.** Спрятанная полоса скрывает сам факт, что
содержимое продолжается: человек видит обрезанный список и уверен, что это весь
список. В дашборде это прямая дезинформация.

Полоса тихая, но заметная: тонкая, без дорожки, полупрозрачная — и заметно
темнее при наведении, чтобы её можно было поймать курсором. Класс `dk-scroll`
на любой области с собственной прокруткой.

Ширину полосы в раскладку не закладываем: на маке полосы наложенные и
появляются только при прокрутке — свёрстанное под их ширину оставит там пустоту.

## Страницы ошибок

Ошибка — это экран продукта, а не заглушка. Текст отвечает на три вопроса
подряд: **что произошло** человеческим языком, **что человек сейчас не видит**,
**что делать** — одно понятное действие, а не список вариантов.

Чего не бывает:

- **обвинения пользователя.** «Страница не найдена», а не «вы ввели неверный
  адрес»: в девяти случаях из десяти виноват не он;
- **технических подробностей на видном месте.** Код нужен поддержке, а не
  читателю — поэтому он внизу и мелко. Но он есть: без него человек не сможет
  объяснить, что у него сломалось;
- **юмора.** Смешная картинка на месте сломанного отчёта раздражает того, кому
  этот отчёт был нужен к совещанию.

Внутри виджета ошибка живёт компактнее (`.dk-widget .dk-error`): незачем ронять
весь дашборд из-за одного сломавшегося блока.

Как сформулированы сами тексты — в разделе «Язык интерфейса»: правила там общие
для кнопок, заголовков, пустых состояний и ошибок.

## Графики

Собраны на [Apache ECharts](https://echarts.apache.org/) (Apache-2.0). Библиотека
лежит в репозитории, а не подтягивается с сети: дашборд должен открываться и без
интернета.

```js
dkChart(document.querySelector('#score'), {
  type: 'line',
  categories: ['09.09', '10.09', '11.09'],
  series: [{ name: 'Средний балл', data: [21, 22, 20] }]
});
```

Типы: `line`, `area`, `bar`, `bar-h`, `bar-stacked`, `pie`, `donut`, `radar`, `sankey`.

**Тема выводится из токенов, а не пишется отдельно.** Поменялся цвет серии —
пересобрал тему, и все графики во всех дашбордах поменялись вместе с ним:

```bash
python3 tools/build-chart-theme.py
```

Написанная руками тема через месяц разошлась бы с системой, и никто бы этого
не заметил — она лежит в другом файле.

### Какой график выбрать

Сначала вопрос, который задают реже всего: **а нужен ли график вообще.**

| Данные | Что показать | Не надо |
|---|---|---|
| Одно текущее значение (+ тренд) | KPI-плитка: число, изменение, спарклайн | столбчатый график из одного столбца |
| Несколько главных чисел | ряд KPI-плиток | группированные столбцы |
| Число, ради которого сделан дашборд | крупная цифра, `Metric XL` | — |
| Одно отношение к пределу | полоса-индикатор | круговая из двух секторов |
| Больше семи значимых категорий | таблица, или таблица плюс график | ещё больше цветов |

Если график всё-таки нужен, тип выбирается **по работе, которую должен
проделать читатель**:

| Читатель должен… | Тип | Цвет кодирует |
|---|---|---|
| сравнить величины | столбцы; горизонтальные при длинных названиях | величину, один тон |
| увидеть динамику | линия; область для одной серии | величину или одну серию |
| увидеть направление в плитке размера S | спарклайн — без осей и легенды | одну серию |
| различить серии между собой | группированные или накопительные столбцы, несколько линий | принадлежность |
| заметить одну серию на фоне прочих | **выделение**: одна акцентом, остальные серым | акцент плюс серый |
| понять, выше или ниже нормы | столбцы от нулевой линии, линия против базовой | полярность |
| увидеть состав целого | накопительные столбцы; горизонтальные при длинных названиях | принадлежность |
| сравнить «было — стало» по каждому | парные точки с перемычкой | один тон, два оттенка |
| сравнить профиль по многим осям | лепестковая | принадлежность, до трёх серий |
| проследить поток через этапы | санкей | принадлежность |
| увидеть долю от целого | пончик, до шести секторов | принадлежность |
| понять, связаны ли две величины | точечный | принадлежность |
| отделить прогноз от факта | линия с пунктирным хвостом | ту же серию |
| показать величину, меняющуюся скачком | ступенчатая линия | величину или серию |

### Каждый вид: когда не брать и что услышит скринридер

График нарисован на холсте, и для скринридера холст пуст. Поэтому `dkChart`
сам ставит контейнеру `role="img"` и подпись, собранную из тех же данных:
крайние значения с категориями, последнее значение у времени, доли у
пончика, норму. Заголовок своими словами — `label` в описании графика. Это
ответ на «что здесь в целом». Точные числа по категориям скринридер
получает только таблицей рядом с графиком. Где число важно — таблица
обязательна.

| Вид | Для чего | Не брать, когда | Скринридеру |
|---|---|---|---|
| `line` | динамика; несколько линий — несколько серий | меньше четырёх точек — плитка с числом; больше шести серий — выделение или малые графики | подпись из данных; точные значения — таблица по датам рядом |
| `area` | динамика одной серии с заливкой | несколько серий — заливки перекрывают друг друга, бери line | подпись из данных; таблица по датам, если значения важны |
| `step` | величина, меняющаяся скачком: тариф, режим, уставка | величина меняется плавно — line | подпись из данных; список изменений с датами |
| `bar` | сравнить величины; несколько серий — группированные столбцы | больше пятнадцати категорий — таблица; длинные названия или телефон — bar-h | подпись с наибольшим и наименьшим; таблица категорий рядом |
| `bar-stacked` | состав целого по категориям | надо сравнить части между категориями точно — группированные bar | подпись из данных; таблица частей по категориям |
| `bar-h` | сравнить величины при длинных названиях и на телефоне | время по оси — line | подпись с наибольшим и наименьшим; рейтинг или таблица рядом |
| `donut` | доля от целого, до шести секторов | больше шести долей или близкие доли — bar-h; важна динамика долей — bar-stacked | подпись с долями в процентах и итогом |
| `pie` | доля от целого; пончик предпочтительнее — в центре встаёт итог | то же, что у donut | подпись с долями в процентах |
| `radar` | профиль по многим осям, до трёх серий | больше трёх серий или осей меньше пяти — bar | подпись по сериям; таблица осей обязательна — форму на слух не передать |
| `sankey` | поток через этапы | этапов меньше трёх — bar-stacked | подпись с числом этапов; таблица «откуда — куда — сколько» обязательна |
| `scatter` | связь двух величин; trend: true — линия наименьших квадратов | точек меньше десяти — таблица; нет второй числовой величины — bar | подпись с разбросом по обеим осям; таблица точек рядом |
| `spark` | направление в плитке размера S, без осей и легенды | нужны значения — график с осями размера M или L | подпись с диапазоном и последним значением; число плитки читается рядом |

Та же таблица — в описи кита: `python3 tools/kit.py charts`.

### Три типа, которые отвечают на отдельные вопросы

**Точечный.** Единственный тип, который отвечает на вопрос «связаны ли две
величины». Обе оси числовые, одна точка — один объект: регион, дом, бригада.
Подписи осей обязательны: категорий здесь нет, и без подписей читатель не
знает, что с чем сравнивают.

```js
dkChart(el, {
  type: 'scatter', trend: true,
  xName: 'износ сетей, %', yName: 'аварий на 100 км',
  series: [{ name: 'Регионы', data: [[42.1, 11.8], [55.3, 17.2], …] }]
});
```

`trend: true` добавляет линию наименьших квадратов. Она включается вручную и
никогда сама: линия показывает направление связи и **ничего не доказывает** —
по трём точкам рисуется так же охотно, как по тремстам. По двум точкам не
строится вовсе: через две точки прямая проходит всегда.

**Пунктирный хвост.** `forecast: n` у серии — последние n точек рисуются
пунктиром.

```js
series: [{ name: 'Аварии', data: […], forecast: 3 }]
```

Сплошная линия — утверждение «так было». Пунктир — «так, скорее всего, будет»
или «эти сутки ещё не закрыты». Рисовать прогноз сплошной линией значит врать,
и это дороже любой экономии на разметке. В легенде хвост отдельной строкой не
стоит: это та же величина, просто не закрытая.

**Ступенчатая линия.** `type: 'step'` — значение держится до следующего замера.
Так ведут себя величины, которые меняются скачком: тариф, режим, статус,
уставка. Наклонная линия между замерами показывала бы плавный переход, которого
не было, — та же ложь, что и сглаживание.

### Три правила, из которых эта таблица следует

**Один тон со шкалой яркости — безопасный выбор по умолчанию.** Темнее значит
больше, и это почти невозможно прочитать неправильно. Разные цвета нужны только
тогда, когда предмет разговора — сами серии.

**Выделение — самая недоиспользуемая форма.** Если история звучит как «вот эта
выросла», то остальные серии это фон, а не участники. Покрасить их все разными
цветами значит спрятать ту единственную, ради которой график и сделан.

```js
dkChart(el, { type: 'line', series: [...], highlight: 'ЮФО' });
```

**Слишком много серий не лечится добавлением цветов.** Седьмая серия
сворачивается в «Прочее», разносится по отдельным маленьким графикам или
уходит в таблицу. Новый выдуманный цвет при дальтонизме неотличим от уже
существующего — и ломает все проверки разом.

Лестница по числу серий: **1–3** — цвет работает сам; **4** — обязательны
подписи прямо на графике; **5–6** — мягкий предел, нужна легенда; **дальше** —
сворачивать. Для точечных диаграмм и карт, где рядом может оказаться любая
пара, предел жёстче — **три**.

### Что обёртка делает сама

Берёт тему по `data-theme` и переключает вместе со страницей. Подстраивается под
размер контейнера. Показывает «данных нет» вместо пустого прямоугольника.
Включает легенду от двух серий и выключает при одной. Пересчитывает подписи
после загрузки шрифта — иначе их ширины считаются по запасной гарнитуре и
легенда наезжает сама на себя.

### Чего обёртка не позволит

**Двух вертикальных осей на одном графике.** Самая частая ложь в дашбордах: две
шкалы разного масштаба создают любое нужное впечатление, потому что их взаимное
положение выбрал автор, а не данные. Нужны две величины — это два графика или
приведение к общей базе.

**Сглаживания линии.** Плавная кривая между точками показывает значения, которых
не было.

**Больше шести секторов в круговой.** Лишние сворачиваются в «Прочее», в консоль
уходит предупреждение. Дальше человек доли не сравнивает, а пересчитывает.

### Цвет серии и цвет состояния — разные вещи

Цвет серии отвечает на вопрос «кто это» (`--series-1…6`), цвет состояния — «насколько
всё плохо» (`--crit`, `--high`, `--calm`). В одном графике может быть либо то, либо
другое, но никогда оба сразу: иначе читатель не поймёт, красная линия — это третья
серия или тревога.

## Типографика

Golos Text. Пятнадцать именованных стилей, имена английские и те же, что в
фигме — `H1` там это `dk-h1` здесь.

| Стиль | Кегль / интерлиньяж | Насыщ. | Для чего |
|---|---|---|---|
| Display | 40 / 44 | 700 | одно число на весь экран |
| H1 | 28 / 32 | 600 | заголовок страницы |
| H2 | 24 / 28 | 600 | заголовок раздела |
| H3 | 20 / 24 | 600 | заголовок виджета |
| H4 | 16 / 20 | 600 | подзаголовок внутри виджета |
| Body L | 16 / 24 | 400 | вводный абзац |
| Body | 14 / 20 | 400 | основной текст |
| Body Bold | 14 / 20 | 600 | выделение внутри основного |
| Caption | 12 / 16 | 400 | подписи, единицы, метки осей |
| Overline | 12 / 16 | 600 | заголовок виджета, надзаголовок, шапка таблицы — прописными |
| Code | 14 / 20 | mono | имена токенов, идентификаторы |
| Metric Hero | 56 / 56 | 600 | одно число на весь экран в главной карточке, Golos |
| Metric XL | 40 / 44 | 600 | главное число сводки |
| Metric L | 28 / 32 | 600 | число в крупной плитке |
| Metric | 20 / 24 | 600 | число в KPI-плитке |

Два правила, из которых всё следует:

**Кегли только чётные, межстрочные кратны четырём.** Интерфейс стоит на сетке
в 4 пикселя; нечётное значение с неё сваливается, и строка начинает ездить
относительно иконок и соседних блоков.

**Имя говорит, что это за текст, а не какого он размера.** Поменяется кегль —
`H1` останется `H1`, и вёрстку переписывать не придётся.

Числа — отдельная ветка (`Metric*`). Одиночное крупное число набирается
пропорциональными цифрами, колонка чисел — тем же Golos Text с запросом
табличных цифр и описанным ограничением (раздел «Шрифт и числа»).

Применяется либо готовым классом, либо токеном:

```css
.my-widget-title { font: var(--type-h3); letter-spacing: var(--type-h3-track); }
```

## Язык интерфейса

Интерфейс разговаривает с человеком постоянно: подписью кнопки, заголовком
виджета, строкой «ничего не найдено», форматом числа. Это такая же система, как
цвет и ритм, и правила у неё такие же жёсткие. Без них один экран говорит
«Сформировать», другой «Построение», третий «ОК» — и человек каждый раз заново
гадает, что случится после нажатия.

### Кнопка

**Кнопка называет действие, а не согласие.** Человек часто читает только
кнопку: вопрос над ней он пропускает. Поэтому подпись обязана сама отвечать на
«что будет, если нажму».

| Так | Не так | Почему |
|---|---|---|
| Построить отчёт | ОК | «ОК» не говорит, что произойдёт |
| Удалить 23 региона | Продолжить | опасное действие называется прямо и с числом |
| Отмена | Нет | пара — это действие и отказ, а не «да» и «нет» |
| Показать все 89 | Ещё | человек должен знать, сколько ещё |
| Сохранить срез | Подтвердить | подтвердить — что? |
| Скачать CSV | Экспорт | называем результат, а не процесс |

**Глагол в инфинитиве.** «Построить отчёт», а не «Построение отчёта» и не
просто «Отчёт»: существительное называет вещь, а кнопка обещает действие.

**Одно-два слова, три — предел.** Кнопка не предложение. Если действие не
называется коротко — скорее всего, оно делает больше одной вещи.

**Первое слово с прописной, точки в конце нет.** Точка превращает подпись в
фразу, а фраза просит, чтобы её дочитали.

### Заголовки и подписи

**Заголовок виджета — существительное.** «Аварии по дням», а не «Посмотреть
аварии» и не «Сколько аварий?». Виджет называет то, что показывает; вопросы
задаёт человек, а не дашборд.

**И он короткий.** Заголовок виджета набран прописными и приглушённым цветом:
его читают один раз, когда ищут нужный блок глазами, а данные внутри читают
каждый раз заново. Крупный светлый заголовок отбирает первый взгляд у числа,
ради которого виджет и стоит на странице. Длинная фраза прописными читается
заметно хуже обычной строки — и это правильное давление: «Аварии по дням» лучше,
чем «Динамика количества аварийных ситуаций за выбранный период».

**Подпись поля стоит над полем, а не внутри.** Плейсхолдер исчезает при вводе,
и человек, отвлёкшись, перестаёт понимать, что он заполняет. Внутри поля —
пример значения, а не название.

**Подсказка объясняет, а не повторяет.** «Источник → тема → уровень риска» —
подсказка. «Информация» — шум.

### Числа

- Разряды делим неразрывным пробелом: `1 234 567`. Точка и запятая в разрядах
  спорят с десятичным разделителем.
- Единица стоит при числе, а не в заголовке: `42 мин`, а не «Время, мин» с
  голым числом внизу — заголовок читают один раз, число каждый раз.
- Изменение всегда со знаком: `+18%`, `−6%`. Знак «минус», а не дефис.
- **Ноль и «нет данных» — разное.** Ноль это ответ: аварий не было.
  Отсутствие — не ответ: мы не знаем. Показывать одинаково нельзя, иначе
  дашборд врёт молчанием.
- Округление внутри одной колонки одинаковое, иначе числа перестают
  сравниваться взглядом.

### Время

- Свежее — относительно: «2 минуты назад». Старше суток — датой: «14 сентября».
  «14 дней назад» человек всё равно пересчитывает в дату, и ошибается.
- На дашборде всегда видно, **на какой момент данные**. Цифра без времени — это
  цифра неизвестной свежести, то есть бесполезная в мониторинге.

### Тон

**Ровный.** Без извинений, восклицательных знаков и «Упс». Человек пришёл
работать, а не мириться с интерфейсом.

**Не пугать и не смягчать.** Высокий риск называется высоким риском.
«Требует внимания» вместо «высокий риск» — это не вежливость, а потеря смысла.

**Система не говорит о себе.** «Данных нет», а не «Я не смог найти данные» и не
«Нам не удалось загрузить». Читателю важно состояние данных, а не переживания
программы.

**Одна вещь называется одинаково везде.** Если это «регион», то не «субъект» на
соседнем экране и не «область» в подсказке. Синонимы в интерфейсе читаются как
разные сущности.

### Пустые состояния

Тот же порядок, что у ошибок: **что произошло → почему → что делать.**

> **Ничего не найдено.** Под фильтры не попал ни один регион.
> Снимите фильтр по округу.

Пустое состояние без третьей строки — тупик: человек видит, что пусто, и не
знает, его это вина или системы. Подробнее — в разделе «Страницы ошибок»: там
те же три вопроса, только на весь экран.

## Что взято из фигмы и что пришлось поправить

Цвета выгружены из переменных файла UI KIT, а не срисованы с экрана. Имена
токенов повторяют пути переменных фигмы. Четыре места пришлось изменить, и
каждое — из-за проверки, а не из-за вкуса:

0. **Гарнитура.** В ките Open Sans, в работающей витрине и в UI-конституции —
   Golos Text. Взят Golos: сделан под кириллицу, ровный ритм в плотных таблицах,
   настоящие табличные цифры. Замена обратно — одна строка в примитивах.

1. **Вторичный текст в светлой теме.** В ките он один на обе темы — `#A9B2C2`.
   На светлом фоне это 1.96:1 при норме 4.5:1: подписи и названия фильтров
   практически не читаются. Взята ступень `gray/400` из того же кита — 5.04:1.

2. **Статусные цвета на тексте.** Заливке хватает 3:1, цифре нужно 4.5:1.
   Жёлтый даёт 2.32:1 на белом, зелёный 2.80:1, красный 2.95:1 на тёмном.
   Поэтому у состояния два набора: `--crit` для заливок и `--crit-ink` для
   текста. Тона те же, ступени разные.

3. **Порядок цветов графика.** Правило кита «использовать по порядку до 6» мы
   сохранили, а сам порядок поменяли. Прежний брал по две ступени одной
   лестницы: бирюза 600 и бирюза 400 дают ΔE 11.1 при пороге 15 — такие серии
   не различит и человек с нормальным зрением. Теперь шесть серий это шесть
   **разных** тонов из тех же лестниц, порядок подобран перебором и проходит
   все проверки в обеих темах.

4. **Фон страницы в светлой теме углублён.** Поверхности кита различаются на
   1.05:1 — при отсутствии обводок И теней виджет на таком фоне не читается.
   Фон опущен до ступени 1.19:1, сопоставимой с тёмной темой (1.18:1). Цвет не
   выдуман: это фон кита, смешанный с его же серой лестницей. Сам виджет
   остался ровно таким, как в ките.

Чего в ките нет и что живёт в библиотеке: фиолетовый слой событий (пришёл из
работающей витрины ЖКХ), серый «данных мало» и пять акцентных тонов.
Кандидаты на перенос в фигму.

## Связь с ai-ops

Шрифт и часть токенов общие с UI-конституцией в `~/ai-ops-kit/standards/uiux`.
Конституция описывает правила, эта библиотека их выполняет. Дашбордного слоя —
KPI, графиков, периодов, серий — в конституции пока нет; он появится там отдельно,
чтобы валидатор мог ловить сборку мимо системы.

## Чего ещё нет

Для мониторинговых дашбордов кит закрыт. Осталось то, что нужно только
ERP-сценарию и сознательно отложено:

**Канбан-доски** — колонки со счётчиками, карточки с аватарами и сроками,
перетаскивание. Единственный кусок, который тянет за собой новое поведение,
а не только вёрстку.

**Ленты истории и обсуждения** — «13.08, 19:16 — Бэклог → Готово» и реплики с
автором, датой и меткой источника. Нужны карточке задачи.

**Тепловой карты календаря** — плотность за период (12 недель коммитов).
Календарь событий у нас есть, календарь плотности — другой инструмент.

### Переключатель темы

Во всех продуктах используйте сегмент `dk-seg dk-seg--icons` с солнцем и луной.
Видимая подпись «Тема» не нужна. Группа сохраняет `aria-label="Тема"`, кнопки —
доступные названия «Светлая тема» и «Тёмная тема», а выбранная кнопка — `aria-pressed`.
Атрибуты `data-theme-set="light"` и `data-theme-set="dark"` обрабатывает общий
`js/dk-theme.js`: он применяет, сохраняет и синхронизирует выбор.
Не добавляйте собственные стили или обработчики темы на уровне продукта.

## Динамические смысловые цвета и отсутствие данных

В JavaScript используйте `dkMeaning(name, role)`: `name` — `crit`, `high`,
`calm`, `event`, `nodata`; обязательная `role` — `text` или `fill`.
Например, `el.style.color = dkMeaning('crit', 'text')`. Для canvas:
`dkMeaning.color('crit', 'fill', el)` разрешает токен в ближайшем `.dk-root`.
Неизвестные роли/имена вызывают TypeError. Event в тексте нейтрален: его заливка
не гарантирует текстовый контраст. Статическая CSS/HTML-разметка сохраняет токены;
JS не конструирует их руками. `tools/check.py` проверяет литералы и сборку
`var(--' + …)`, но не доказывает отсутствие всех возможных способов обфускации.

Отсутствие наблюдений — не ноль и не «вне среза». `dk-nodata` добавляет тихую
серую заливку с контрастными штрихами; рядом обязательно «Нет данных» или
доступное имя. Для ячейки таблицы: `<td class="dk-nodata">Нет данных</td>`.
Карта использует texture/decal для отсутствующих регионов, плитки и uptime —
тот же CSS-паттерн. Сектор `palette:'status'` с индексом 3 получает штриховку.
Временные ряды сохраняют `null` как разрыв: штриховать весь фон графика нельзя,
поскольку это скроет границы пропуска. Доля данных без наблюдений должна быть
названа в числовой альтернативе; текст не заменяется одним паттерном.

## SDK: контекст, анализ и рабочий срез

Новые optional-файлы подключаются через `python3 tools/kit.py head <части>`:
`dk-analysis.js` (heatmap, bullet, period comparison, timeline annotations),
`dk-context.js` (tooltip), `dk-workspace.js` (state, saved views, density,
fullscreen/export), `dk-tree.js`, `dk-layout-editor.js`. Runtime-зависимостей
не добавлено. Breadcrumbs — CSS/HTML; details sidebar — вариант существующего
`dkModal`, без второго modal engine. Все 13 частей доступны в каталоге,
component pages и machine-readable manifest. Новые JS-возможности помечены
экспериментальными: контракт проверен, production-полевых данных ещё нет.

Каждая component page содержит выбор/замену, markup, API, состояния,
ограничения, accessibility/responsive и файлы подключения. Примеры с `<script>`
выполняются после разметки и подключения файлов; на страницах документации
инициализация ждёт DOMContentLoaded. Не вызывайте initializer раньше deferred JS.

Старые `set`, `clear`, `setOptions`, `setTotal`, `goTo`, `setValues`, `setScope`
сохранены. Новые `update` восстанавливают состояние без user-callback там,
где это описано; table синхронизирует выбор через прежний onSelect. `destroy`
идемпотентен, повторная инициализация освобождает предыдущий экземпляр. Обёртки
charts и map сохраняют прежний API и automatic disposal.

```js
const state = dkState(stateHost, {
  filters: {service: 'heat'}, period: '14d',
  sort: {column: 'risk', dir: 'desc'}, page: 1, size: 20,
  mode: 'map', density: 'comfortable'
}, {url: 'view'}); // url optional, JSON snapshot в query
stateHost.addEventListener('dk:statechange', ({detail}) => {
  // Host вычисляет один dataset из detail.filters/period,
  // затем обновляет KPI, графики, карту, таблицу и pager.
  // Старый onSort использует ascending/descending: адаптируйте к asc/desc.
});
dkSavedViews(viewsHost, {key: 'my-dashboard.views', state});
```

`get()` возвращает копию; filters — строки/массивы строк, period — строка/null,
sort — column/dir, pagination — положительные integers. Thresholds остаются
настройкой показателя, не персональным фильтром. Saved views v1 хранит снимок;
v0 views мигрирует, неизвестные версии не перезаписываются. При отказе storage
состояние доступно в памяти и UI сообщает ограничение. Виды локальны для origin
и не синхронизируются между людьми/устройствами. CSV получает текущий filtered
state от host; экспорт DOM-страницы вместо dataset не выполняется.

## Полный цикл проверок

`python3 tools/check.py --fast` — статические правила; `python3 tools/check.py`
добавляет браузерную адаптацию. `python3 tools/test.py` — полный fail-closed suite:
Node 22+/Chrome обязательны, JS syntax, generated files/manifest, 46 страниц ×
3 размера, select/chips/meaning/advanced runtime regressions, 200% font tokens,
320px reflow, AX names/ID references, PNG/decal и SDK eval fixtures. При отсутствии
Chrome suite падает, а не выдаёт пропуск за полный успех. CI запускает этот suite;
`DK_EVIDENCE_DIR` сохраняет JSON runtime, artifact привязан к SHA. Исторические
снимки 30.09 остаются reference evidence, не автоматическим pixel baseline.

Skill evals содержат новые задания. `check-evals.py` доказывает наличие частей,
examples/anti-patterns/a11y и dependency closure; это не независимый прогон
AI-агента. В полной проверке отдельно выполняются реальные API/UI regressions.

CI security boundary: в приватном репозитории CodeQL и Scorecard остаются
capability-gated. Их skipped job не подтверждает SAST/supply-chain аудит.
API branch protection на текущем тарифе отвечает 403; защита main не доказана.
Dashboard workflow имеет read-only permissions, checkout без сохранения
credentials, pinned action SHAs и ограниченные timeout; Dependabot обновляет
GitHub Actions. Runtime artifacts привязаны к head SHA, не смешиваются с baseline.

На сводке временной график расположен до второстепенных KPI: 521px от верха
при 390×844 против прежних 793px. Состав риска виден ещё раньше. Кнопки графика
сохраняют PNG и переключают полный экран; источника обновления у demo нет,
поэтому «Обновить» отключено.

Calendar week на узком экране или coarse pointer отображается agenda по дням
со временем текстом и кнопками 44px. Часовая сетка сохранена для desktop/fine;
update({events,view}) и destroy() дополняют прежний API.
